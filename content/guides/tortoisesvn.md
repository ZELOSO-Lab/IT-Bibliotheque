# TortoiseSVN 技術まとめ

## 基礎

TortoiseSVN は、Windows のエクスプローラーに組み込まれる Subversion クライアントです。フォルダやファイルを**右クリックして「SVN 更新」「SVN コミット」などを選ぶだけ**で操作でき、状態はファイルアイコンに重ねて表示されます。コマンドを使わない開発者・設計書を管理する業務担当者まで幅広く使われています。

このページは GUI 操作に絞っています。`svn` コマンドでの操作は「SVN」のページ、サーバー側のリポジトリ構築や権限設定は「Apache Subversion」のページを参照してください。

### 主な用途

- エクスプローラーからのチェックアウト・更新・コミット
- 差分・履歴（ログ）・注釈（誰がいつ変えたか）の確認
- 競合の解決（TortoiseMerge）
- リリース前の変更確認、ブランチ・タグの作成とマージ

### 同梱ツール

| ツール | 役割 |
| --- | --- |
| TortoiseProc.exe | 右クリックメニューから呼ばれる本体。コマンドラインから呼び出して自動化もできる |
| TortoiseMerge | 差分表示・競合解決・パッチ適用のツール |
| TortoiseBlame | 注釈（行ごとの最終変更者）の表示 |
| TortoiseIDiff | 画像の差分表示 |
| TSVNCache.exe | アイコン表示のために作業コピーの状態を監視する常駐プロセス |
| svn.exe など | インストール時に「command line client tools」を選んだ場合のみ |

### オーバーレイアイコンの意味

| アイコン | 状態 | 次にやること |
| --- | --- | --- |
| 緑のチェック | 変更なし（最新とは限らない） | 作業前に SVN 更新 |
| 赤の「!」 | 変更あり | 差分を確認してコミット |
| 黄色の「!」 | 競合 | 競合を解決してからコミット |
| 青の「+」 | 追加予定 | コミットで登録される |
| 赤の「×」 | 削除予定 | コミットで削除される |
| 錠前 | ロック中 | 編集が終わったらコミット（ロックは自動で解放） |
| アイコンなし | 管理対象外、または表示数の上限超え | 「実務Tips」のアイコン表示の項を参照 |

緑のチェックは「**手元で変更していない**」という意味で、サーバーの最新と同じとは限りません。最新かどうかは「変更をチェック」→「リポジトリをチェック」で確認します。

## 環境構築

### 1. インストール

1. 公式サイト（tortoisesvn.net）のダウンロードページから、**64bit 版の MSI** をダウンロードする
2. 同じページの言語パックから**日本語（Japanese）**の MSI もダウンロードする（本体と同じバージョン・同じ bit 数を選ぶ）
3. 本体をインストールする。svn コマンドも使うなら、機能選択で **「command line client tools」** を「ローカルにインストール」に変更する
4. 言語パックをインストールする
5. 任意のフォルダで右クリック →「TortoiseSVN」→「Settings」→「General」→「Language」で **日本語** を選ぶ

Windows 11 では、右クリックメニューの「その他のオプションを確認」（Shift + F10）の中に TortoiseSVN のメニューが表示される場合があります。

### 2. 最初に見直す設定（右クリック →「TortoiseSVN」→「設定」）

| 設定箇所 | 内容 | おすすめ |
| --- | --- | --- |
| 一般 → Subversion → グローバル無視パターン | コミット対象から外すファイル | `bin obj *.suo *.user .vs Thumbs.db ~$*` |
| アイコンオーバーレイ → ステータスキャッシュ | 状態の調べ方（既定 / シェル / なし） | 通常は既定。重い場合は「シェル」 |
| アイコンオーバーレイ → 除外パス / 含めるパス | アイコン監視の対象 | 作業フォルダ（例: `C:\work\*`）だけを含める |
| ネットワーク | プロキシ・SSH クライアント | 社内プロキシを経由する場合に設定 |
| 差分ビューアー | 外部差分ツール | WinMerge などに変更可能 |
| 保存されたデータ → 認証データ | 保存済みのユーザー名・パスワード | パスワード変更後はここで「消去」 |

`~$*` は Office が編集中に作る一時ファイル（`~$設計書.xlsx` など）です。無視しておくと誤コミットを防げます。

設定ファイルと認証キャッシュは `%APPDATA%\Subversion\` にあり、svn コマンドと共有されます。

### 3. 最初のチェックアウト

1. 作業用フォルダ（例: `C:\work\project`）を作る
2. フォルダを右クリック →「SVN チェックアウト」（SVN Checkout）
3. 「リポジトリの URL」に `https://svn.example.com/repos/project/trunk` を入力
4. 認証ダイアログでユーザー名・パスワードを入力し、「認証の保存」にチェック
5. 完了後、フォルダに緑のチェックが付けば成功

## コマンド

TortoiseSVN の操作は**右クリック → TortoiseSVN メニュー**から行います。メニュー名は言語パックのバージョンで多少異なるため、英語名を併記します。

### 基本操作

| 操作 | メニュー | 補足 |
| --- | --- | --- |
| 取得 | SVN チェックアウト（SVN Checkout） | 空のフォルダで実行 |
| 最新化 | SVN 更新（SVN Update） | 作業前・コミット前に必ず |
| 反映 | SVN コミット（SVN Commit） | ダイアログで差分を確認できる |
| コミット前の確認 | 変更をチェック（Check for modifications） | 「リポジトリをチェック」でサーバー側の更新も表示 |
| 過去の版にする | 更新（リビジョン指定）（Update to revision） | 確認が終わったら「SVN 更新」で最新に戻す |

### ファイル操作

| 操作 | メニュー | 注意点 |
| --- | --- | --- |
| 追加 | 追加（Add） | コミットダイアログの「バージョン管理外のファイルを表示」でも追加できる |
| 削除 | 削除（Delete） | エクスプローラーの Delete キーで消すと「!」（行方不明）になる |
| 名前変更 | 名前の変更（Rename） | エクスプローラーで直接変えると履歴が切れる |
| 移動 | 右ボタンでドラッグ →「SVN 移動（ここへ）」 | 履歴を引き継いで移動できる |
| 変更を取り消す | 元に戻す（Revert） | 未コミットの変更は**元に戻せない**ので慎重に |
| 無視 | 無視リストに追加（Add to ignore list） | 親フォルダの `svn:ignore` を変更するのでコミットが必要 |

### 履歴・差分

| 操作 | メニュー |
| --- | --- |
| 作業コピーとの差分 | 差分（Diff） |
| 直前の版との差分 | 以前のバージョンと差分（Diff with previous version） |
| 履歴を見る | ログを表示（Show log） |
| 誰がいつ変えたか | 注釈（Blame） |
| ブランチの流れを見る | リビジョングラフ（Revision graph） |
| サーバーの中を見る | リポジトリブラウザー（Repo-browser） |

ログ画面でよく使う右クリックメニュー:

| メニュー | 動き |
| --- | --- |
| 作業コピーと比較 | 選んだ版と手元のファイルの差分 |
| リビジョンを比較（2つ選択） | 2つの版の差分 |
| このリビジョンの変更を元に戻す（Revert changes from this revision） | その1コミットだけを打ち消す変更を作業コピーに作る |
| このリビジョンに復元（Revert to this revision） | その版以降の変更をすべて打ち消す |
| 統合ログを含める（Include merged revisions） | マージで取り込んだ元のコミットも表示 |

どちらの「元に戻す」も**作業コピーに変更が入るだけ**です。内容を確認してからコミットして初めてサーバーに反映されます。

### ブランチ・ロック・トラブル対応

| 操作 | メニュー |
| --- | --- |
| ブランチ・タグの作成 | ブランチ/タグ（Branch/tag） |
| ブランチへ切り替え | 切り替え（Switch） |
| ブランチを取り込む | マージ（Merge） |
| 排他ロック | ロックを取得（Get lock） / ロックを開放（Release lock） |
| 競合の解決 | 競合の編集（Edit conflicts）→ 解決済み（Resolved） |
| 中断後の復旧 | クリーンアップ（Clean up） |
| サーバー URL の変更 | 再配置（Relocate） |
| .svn なしで取り出す | エクスポート（Export） |
| パッチ | パッチを作成（Create patch） / パッチを適用（Apply patch） |

## サンプル

### 毎日の作業手順

1. 作業フォルダを右クリック →「SVN 更新」
2. ファイルを編集する
3. 右クリック →「SVN コミット」を開く
4. 一覧の各ファイルを**ダブルクリックして差分を確認**する（TortoiseMerge が開く）
5. 「バージョン管理外のファイルを表示」にチェックし、追加すべき新規ファイルが漏れていないか確認する
6. メッセージ欄にチケット番号と内容（例: `#1234 帳票出力の文字化けを修正`）を書いて OK

コミット時に「古くなっています（out of date）」と出たら、いったんキャンセルして「SVN 更新」してから再度コミットします。

### 競合を GUI で解決する

1. 「SVN 更新」で競合が出ると、ファイルが黄色の「!」になり、`.mine`・`.r1233`・`.r1240` などの補助ファイルができる
2. ファイルを右クリック →「競合の編集」で TortoiseMerge を開く
3. 上段が「相手の版（Theirs）」と「自分の版（Mine）」、下段が「マージ結果（Merged）」
4. 赤い競合ブロックを右クリックし、相手のブロックを使う（Use 'theirs' text block）・自分のブロックを使う（Use 'mine' text block）などを選ぶか、下段を直接編集する
5. 保存し、ツールバーの「解決済みにする」（または右クリック →「解決済み」）を実行
6. ビルド・動作確認してからコミット

Excel・Word などのバイナリは行単位のマージができません。自分の版を別名で保存しておき、「解決」ダイアログで「自分のバージョン」または「相手のバージョン」を丸ごと選んだうえで、手作業で反映します。

### ブランチを作って trunk に戻す

1. trunk の作業コピーを右クリック →「ブランチ/タグ」
2. 「コピー先の URL」に `/branches/feature-login` を指定し、「作業コピーを新しいブランチに切り替える」にチェック
3. ブランチで開発・コミット
4. 完成したら trunk の作業コピーに「切り替え」→「SVN 更新」
5. 右クリック →「マージ」→「リビジョン範囲をマージ」→ URL に `/branches/feature-login` を指定
6. 「テストマージ」で結果を確認してから「マージ」を実行し、差分を確認してコミット

### Excel 設計書をロックして編集する

1. 管理者（またはリーダー）がファイルに `svn:needs-lock` プロパティを設定してコミットしておく（右クリック →「プロパティ」→「新規」→「Needs-lock」）
2. 利用者の手元ではファイルが**読み取り専用**になる
3. 編集前に右クリック →「ロックを取得」。他の人がロック中なら取得できない
4. 編集してコミットすると、ロックは自動で解放される（コミットダイアログの「ロックを保持」をオンにした場合を除く）

### TortoiseProc で操作を自動化する

```bat
@echo off
rem 朝いちで複数の作業コピーをまとめて更新するバッチ
set TSVN="C:\Program Files\TortoiseSVN\bin\TortoiseProc.exe"
%TSVN% /command:update /path:"C:\work\project-a*C:\work\project-b" /closeonend:2
```

| `/closeonend` の値 | 動き |
| --- | --- |
| `0` | 自動で閉じない |
| `1` | エラーがなければ閉じる |
| `2` | エラー・競合がなければ閉じる |
| `3` | エラー・競合・マージがなければ閉じる |

`/command:` には `commit`、`log`、`diff`、`cleanup`、`repobrowser` なども指定できます。複数パスは `*` で区切ります。

## エラー対応

TortoiseSVN のエラーは svn コマンドと同じ `E` 番号付きで表示されます。番号で検索すると情報が見つかりやすくなります。

| エラーメッセージ | 主な原因 | 対処 |
| --- | --- | --- |
| `E155004: Run 'svn cleanup' to remove locks` | 更新・コミットの中断、エクスプローラーの異常終了 | 作業コピーのルートで「クリーンアップ」 |
| `E155037: Previous operation has not finished; run 'cleanup' if it was interrupted` | 前回の操作が途中で止まった | 「クリーンアップ」 |
| `E155011: File '...' is out of date` | 他の人が先に同じファイルをコミット | 「SVN 更新」してから再コミット |
| `E155015: Aborting commit: '...' remains in conflict` | 競合が未解決 | 「競合の編集」→「解決済み」 |
| `E195022: File '...' is locked in another working copy` | 他の人がロック中 | 「変更をチェック」→「リポジトリをチェック」でロック所有者を確認し、連絡する |
| `E155036: Please see the 'svn upgrade' command` | 古いバージョンで作った作業コピー | 右クリック →「作業コピーのアップグレード」（SVN Upgrade working copy） |
| `E155021: This client is too old to work with the working copy` | 新しい TortoiseSVN / svn で作った作業コピーを古い版で開いた | TortoiseSVN（または svn コマンド）を新しい版に揃える |
| `E170001: Authorization failed` | 権限なし、保存した認証情報が古い | 設定 →「保存されたデータ」→ 認証データを「消去」して入れ直す。権限は管理者に依頼 |
| `E230001: Server SSL certificate verification failed` | 社内CA・自己署名証明書 | 表示されるダイアログで証明書を確認し「常に受け入れる」。全社なら証明書の配布を依頼 |
| `E175002` / `E170013` で接続できない | プロキシ、URL 誤り、VPN 未接続 | ブラウザーで URL を開けるか確認。設定 →「ネットワーク」でプロキシを確認 |

### アイコンが表示されない・おかしい

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| すべてのアイコンが出ない | Windows のオーバーレイ表示枠（15個）を OneDrive・Dropbox などが先に使っている | 下記の「アイコン表示の上限」を参照 |
| 状態が更新されない | TSVNCache の更新遅れ | 「クリーンアップ」で「シェルオーバーレイを更新」にチェック。直らなければエクスプローラーを再起動 |
| ネットワークドライブで出ない | 既定でリモートドライブは監視対象外 | 作業コピーはローカルディスクに置く |

### クリーンアップのオプション

| オプション | 用途 |
| --- | --- |
| 作業コピーの状態をクリーンアップ | 通常のロック解除。まずはこれだけで実行 |
| ロックを解除 | 他のプロセスが残したロックも解除 |
| 未バージョン管理のファイルやフォルダーを削除 | ビルド成果物などを一掃（**未登録の新規ファイルも消える**ので注意） |
| すべての変更を再帰的に元に戻す | 作業コピーを初期状態に戻す（**未コミットの変更が消える**） |
| シェルオーバーレイを更新 | アイコンの表示を更新 |

## 実務Tips

### コミット前の確認を習慣にする

- コミットダイアログで**全ファイルの差分を開いて見る**。デバッグ用のコードや個人設定の混入を防げる
- 「変更をチェック」でサーバー側の更新（リポジトリをチェック）も見てから作業を始める
- Excel・Word の差分は TortoiseMerge では見られない。Word 文書は「差分」で Word の比較機能が起動する（同梱スクリプトによる）。Excel は Excel 側の比較機能や専用ツールを使う

### プロジェクトのルールをプロパティで強制する

フォルダのプロパティに次を設定してコミットすると、そのフォルダを使う全員の TortoiseSVN に効きます（svn コマンドには効きません）。

| プロパティ | 効果 |
| --- | --- |
| `tsvn:logminsize` | コミットメッセージの最小文字数（例: `10`） |
| `tsvn:logtemplate` | コミットメッセージのひな形 |
| `bugtraq:url` / `bugtraq:message` | チケット番号入力欄と、ログからチケットへのリンク |

確実に強制したい場合は、サーバー側の pre-commit フックも併用します（「Apache Subversion」のページ参照）。

### アイコン表示の上限

- Windows は**オーバーレイアイコンの登録を15個まで**しか使いません。レジストリ `HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer\ShellIconOverlayIdentifiers` の**名前順で先頭15個**が有効です
- OneDrive・Box・Dropbox などが名前の先頭にスペースを入れて上位を取っていることが多く、TortoiseSVN のアイコンが押し出されます
- 業務 PC ではレジストリ変更に管理者権限が必要なため、情報システム部門と相談します。どうしても表示できない場合でも、「変更をチェック」で状態は確認できます

### 作業コピーの置き場所

- **ローカルディスクの浅いパス**（`C:\work\project`）に置く。ネットワークドライブ・OneDrive 同期フォルダは避ける
- デスクトップやドキュメント直下は OneDrive のバックアップ対象になっていることがあるので注意
- 巨大なリポジトリはルートごとチェックアウトせず、必要なフォルダ（`trunk` など）だけ取得する。チェックアウト時の「チェックアウトの深さ」（Checkout Depth）で直下だけ取得し、必要なフォルダを後から追加で取得できる

### チームで揃えること

- TortoiseSVN のバージョン（少なくとも 1.14 などのマイナーバージョン）をチームで揃える。svn コマンドや IDE のプラグインを併用する場合も同様
- 「名前の変更」「削除」は**必ず TortoiseSVN のメニューから**行う。エクスプローラーで直接操作すると履歴が切れたり「!」になったりする
- パスワード変更後に接続できなくなったら、まず「保存されたデータ」の認証データを消去する
