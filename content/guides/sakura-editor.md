# サクラエディタ 技術まとめ

## 基礎

サクラエディタは、Windows 用の国産・無料（オープンソース）のテキストエディタです。動作が軽く、**正規表現置換・矩形選択・Grep（複数ファイル検索）・文字コード変換**が手軽に使えるため、日本の SIer や運用現場で長く使われています。

「Excel から貼った値を SQL の IN 句にする」「ログから特定のエラーだけ抜き出す」「Shift_JIS のファイルを壊さずに直す」といった、**プログラミング以前の地味なテキスト加工**が得意です。

### 主な用途

- ソース・SQL の整形
- Excel から貼り付けたデータの変換
- ログの調査（Grep）
- 文字コード・改行コードの確認

### まず押さえる用語

| 用語 | 意味 | 現場での注意点 |
| --- | --- | --- |
| 正規表現 | パターンで文字列を検索・置換する記法 | 置換ダイアログの「正規表現」にチェックしないと効かない |
| 矩形選択 | 行をまたいで四角形の範囲を選ぶ操作 | 固定長データの列の削除・コピーに便利 |
| Grep | フォルダ内の複数ファイルをまとめて検索する機能 | 結果をダブルクリックすると該当ファイルの該当行が開く |
| 文字コード | Shift_JIS（SJIS）・UTF-8・EUC-JP など | 保存時に変わると**相手側で文字化け**する |
| 改行コード | CRLF（Windows）・LF（Linux / Mac） | Linux 用のシェルを CRLF で保存すると動かない |
| BOM | UTF-8 ファイル先頭の識別用バイト | 「BOM 付き」を嫌うツールもある（シェル・一部の CSV 取り込み） |
| タイプ別設定 | 拡張子ごとの設定（色分け・タブ幅など） | `.sql` `.java` などで個別にインデントを設定できる |
| 共通設定 | 全体に効く設定（ファイル・バックアップ・キー割り当てなど） | 設定 → 共通設定 から開く |

### ステータスバーで確認できること

画面右下には、**現在の文字コード（例: `SJIS` / `UTF-8`）・改行コード（`CRLF` / `LF`）・行と桁の位置**が表示されます。ファイルを触る前に、まずここを確認する習慣をつけると文字化け事故を防げます。

## 環境構築

### 1. ダウンロードとインストール

公式サイト（https://sakura-editor.github.io/）から最新版を入手します。インストーラー版と zip 版があります。

| 種類 | 特徴 | 向いている場面 |
| --- | --- | --- |
| インストーラー版 | スタートメニュー・右クリックメニューへの登録ができる | 自分の PC で日常的に使う |
| zip 版 | 展開するだけで使える | インストールが禁止されている環境、USB 持ち運び |

インストーラーでは、**エクスプローラーの右クリックメニューに「SAKURAで開く」を追加**しておくと便利です。

### 2. 正規表現ライブラリを確認する

正規表現は外部 DLL（`bregonig.dll`）を使って動きます。現在の配布物には同梱されていますが、古い版や zip を手作業でコピーした環境では欠けていることがあります。

1. 設定 → 共通設定 →「検索」タブを開く
2. 正規表現ライブラリの欄に**バージョンが表示されていれば OK**
3. 表示されない場合は、`bregonig.dll` を `sakura.exe` と同じフォルダに置く

### 3. 最初にやっておく設定

| 設定 | 場所 | おすすめ |
| --- | --- | --- |
| 行番号・改行マーク・タブ・全角空白の表示 | 設定 → タイプ別設定 →「カラー」タブ | 全角空白と改行を見えるようにする |
| タブ幅・折り返し桁数 | 設定 → タイプ別設定 →「スクリーン」タブ | 言語ごとに設定 |
| バックアップ | 設定 → 共通設定 →「バックアップ」タブ | 保存時にバックアップを作る設定にしておく |
| 新規作成時の文字コード | 設定 → タイプ別設定（文字コードの既定値） | チームの方針（UTF-8 / SJIS）に合わせる |
| 前回開いていたファイル・位置 | 設定 → 共通設定 →「ファイル」タブ | カーソル位置の復元を有効にする |
| キー割り当て | 設定 → 共通設定 →「キー割り当て」タブ | よく使うマクロをキーに登録 |

### 4. 動作確認

1. 適当なテキストを開き、`Ctrl+R` で置換ダイアログを開く
2. 「正規表現」にチェックを入れ、置換前 `^`・置換後 `-- ` で「すべて置換」
3. 全行の先頭に `-- ` が付けば、正規表現置換が使える状態です

## コマンド

### よく使うショートカット

| 操作 | キー |
| --- | --- |
| 検索 / 置換 | `Ctrl+F` / `Ctrl+R` |
| 次を検索 / 前を検索 | `F3` / `Shift+F3` |
| Grep（複数ファイル検索） | `Ctrl+G` |
| 指定行へジャンプ | `Ctrl+J` |
| 小文字に変換 / 大文字に変換 | `Ctrl+U` / `Ctrl+Shift+U` |
| 元に戻す / やり直し | `Ctrl+Z` / `Ctrl+Y` |
| すべて選択 | `Ctrl+A` |
| 上書き保存 | `Ctrl+S` |

### 矩形選択

| 操作 | 方法 |
| --- | --- |
| マウスで矩形選択 | `Alt + ドラッグ` |
| キーボードで矩形選択 | `Shift+Alt+矢印キー` |
| 矩形範囲選択の開始 | `Shift+F6` を押してからカーソルを移動 |
| 列を削除 / コピー | 矩形選択して `Delete` / `Ctrl+C` |
| 複数行の同じ桁に文字を入れる | 矩形選択した状態で文字を入力（または矩形でコピーした内容を貼り付け） |

固定長ファイル（ホストの帳票・取込ファイル）の特定の桁だけを取り出す・消すときに便利です。等幅フォントで使います。

### 正規表現置換（`Ctrl+R` →「正規表現」にチェック）

| やりたいこと | 置換前 | 置換後 |
| --- | --- | --- |
| 行頭に付ける | `^` | `-- ` |
| 行末に付ける | `$` | `,` |
| 各行を `'...',` で囲む（IN 句用） | `^(.*)$` | `'$1',` |
| タブ → カンマ | `\t` | `,` |
| 行末の空白を削除 | `[ \t]+$` | （空） |
| 空行を削除 | `^\r?\n` | （空） |
| 全角空白を半角に | `　`（全角空白） | 半角空白1つ |
| 日付 `2026/10/19` → `2026-10-19` | `(\d{4})/(\d{2})/(\d{2})` | `$1-$2-$3` |
| `ERROR` または `FATAL` を含む行を検索 | `ERROR\|FATAL` | — |
| 先頭の連番を削除 | `^\d+\s*` | （空） |

置換後の文字列では、`( )` で囲んだ部分を `$1` `$2` … で参照します。置換は「置換対象」で**選択範囲だけ**にも限定できます。

### よく使う正規表現の記号

| 記号 | 意味 | 例 |
| --- | --- | --- |
| `^` / `$` | 行頭 / 行末 | `^SELECT` |
| `.` | 任意の1文字 | `a.c` |
| `*` / `+` / `?` | 0回以上 / 1回以上 / 0か1回 | `\d+` |
| `\d` / `\s` / `\w` | 数字 / 空白 / 英数字と `_` | `\s+` |
| `[ ]` / `[^ ]` | いずれか1文字 / 以外の1文字 | `[0-9A-F]` |
| `( )` | グループ（置換で `$1` として参照） | `(\w+)=(\w+)` |
| `\|` | または | `WARN\|ERROR` |
| `\t` / `\r` / `\n` | タブ / CR / LF | `\t` |
| `.*?` | 最短一致 | `".*?"` |

### Grep（`Ctrl+G`）

| 項目 | 指定例 | 説明 |
| --- | --- | --- |
| 条件 | `ORA-\d{5}` | 検索文字列（正規表現も可） |
| ファイル | `*.log` / `*.java;*.xml` | 対象ファイルのパターン（`;` 区切りで複数） |
| フォルダ | `C:\work\logs` | 検索するフォルダ |
| サブフォルダも検索 | チェック | 配下のフォルダも対象にする |
| 文字コードセット | 自動選択 / SJIS / UTF-8 | 化ける場合は明示的に指定 |
| 結果出力形式 | ノーマル / ファイル毎 | 該当行の出力方法 |

結果ウィンドウの行をダブルクリック（またはタグジャンプ `F12`）で、該当ファイルの該当行へ移動します。複数ファイルを一括で書き換える場合は、検索メニューの **Grep 置換**を使います（実行前に必ずバックアップを取る）。

### 変換・編集のメニュー操作

| 操作 | メニュー |
| --- | --- |
| 行のソート | 編集 → 高度な操作 → 選択行の昇順ソート / 降順ソート |
| 重複行の削除（連続する重複） | 編集 → 高度な操作 → 選択行のマージ（uniq） |
| 全角・半角の変換 | 変換 → 全角英数→半角英数 など |
| タブ ↔ 空白の変換 | 変換 → TAB→空白 / 空白→TAB |
| 文字コードを指定して開き直す | ファイル → 開き直す → 文字コードを選択 |
| 文字コード・改行コードを変えて保存 | ファイル → 名前を付けて保存 → ダイアログ下部で文字コードセット・改行コード・BOM を指定 |
| 2ファイルの比較 | 検索 → ファイル内容比較 |

「選択行のマージ」は**隣り合う同じ行だけ**をまとめます。重複をすべて消すときは、先にソートしてから実行します。

## サンプル

### Excel の1列から SQL の IN 句を作る

Excel の列をコピーしてサクラエディタに貼り付け、正規表現で置換します。

```text
A001
A002
A003
```

1. 置換前 `^(.*)$` → 置換後 `'$1',` で「すべて置換」
2. 置換前 `\r?\n` → 置換後（空）で改行を消して1行にする
3. 最後の `,` を消して前後に `WHERE code IN (` と `)` を付ける

```sql
WHERE code IN ('A001','A002','A003')
```

### タブ区切り（Excel 貼り付け）から INSERT 文を作る

```text
1	山田	営業部
2	佐藤	総務部
```

置換前 `^(.*)\t(.*)\t(.*)$` → 置換後 `INSERT INTO emp (id, name, dept) VALUES ($1, '$2', '$3');`

```sql
INSERT INTO emp (id, name, dept) VALUES (1, '山田', '営業部');
INSERT INTO emp (id, name, dept) VALUES (2, '佐藤', '総務部');
```

値に `'` が含まれる場合は、先に `'` → `''` に置換してエスケープします。

### ログからエラー行だけを抜き出す

1. `Ctrl+G` で Grep を開き、条件に `ERROR|FATAL`（正規表現にチェック）、ファイルに `*.log`、フォルダにログの場所を指定
2. 結果ウィンドウを「名前を付けて保存」すれば、エラー一覧ファイルになる
3. 時間帯で絞るなら、条件を `^2026-10-19 1[0-2]:.*ERROR` のようにする

### マクロ（JScript）で定型置換をまとめる

`.js` ファイルとして保存し、ツール → 名前を指定してマクロ実行 で実行します。複数の置換を毎回同じ順序で行う作業に使えます。

```javascript
// trim_and_quote.js : 行末の空白削除 → 空行削除 → 各行を '...', で囲む
// 第3引数のオプション: 4 = 正規表現を使う
Editor.ReplaceAll('[ \\t]+$', '', 4);
Editor.ReplaceAll('^\\r?\\n', '', 4);
Editor.ReplaceAll('^(.+)$', "'$1',", 4);
```

JScript の文字列内では `\` を `\\` と書く必要がある点に注意します。よく使うマクロは 設定 → 共通設定 →「マクロ」タブで登録し、「キー割り当て」タブでショートカットを割り当てると1キーで実行できます。

### キーマクロの記録

決まった手順を繰り返すだけなら、キーマクロが手軽です。

1. ツール → キーマクロの記録開始
2. 普段どおりに操作する（カーソル移動・入力・置換など）
3. ツール → キーマクロの記録終了
4. ツール → キーマクロ実行 で同じ操作を再生する。ツール → キーマクロの保存 で `.mac` ファイルに残せる

## エラー対応

| 症状・メッセージ | 主な原因 | 対処 |
| --- | --- | --- |
| 「正規表現」のチェックが付けられない／正規表現で検索できない | `bregonig.dll` が見つからない | 共通設定「検索」タブでライブラリ表示を確認し、`bregonig.dll` を `sakura.exe` と同じフォルダに置く |
| 正規表現で置換したのに何も変わらない | 「正規表現」にチェックがない、置換対象が「選択範囲」になっている | ダイアログのチェック項目と置換対象を確認 |
| 開いたら文字化けしている | 文字コードの自動判別ミス（短い SJIS ファイルなど） | ファイル → 開き直す → 正しい文字コード（SJIS / UTF-8 など）を選ぶ |
| 保存したら相手側で文字化けした | 保存時の文字コードが変わった、BOM の有無 | 名前を付けて保存で文字コードセット・BOM を明示する。ステータスバーで確認 |
| Linux で `/bin/bash^M: bad interpreter: No such file or directory` | シェルスクリプトを CRLF で保存した | 名前を付けて保存で改行コードを **LF** にして保存し直す |
| Linux で `$'\r': command not found` | 同上（CRLF が混入） | LF で保存し直す。部分的に混在していないかも確認 |
| CSV を Excel で開くと文字化け | UTF-8（BOM なし）を Excel が SJIS として読んだ | 用途に合わせて SJIS で保存するか、UTF-8 の **BOM 付き**で保存する |
| Grep で日本語がヒットしない・結果が化ける | 対象ファイルと Grep の文字コードセットが合っていない | Grep ダイアログで文字コードセットを明示する |
| 置換したら改行が消えすぎた | `\s` が改行も含むため、`\s+` が改行ごと置換した | 空白だけを対象にするなら `[ \t]+` を使う |
| 大きなログを開くと重い | 数百 MB 以上のファイル | Grep で必要な行だけ抜き出す。または `findstr` や Linux 側の `grep` で絞ってから開く |
| 誤って上書き保存してしまった | — | `Ctrl+Z` は閉じるまで有効。閉じた後はバックアップ設定のファイル（`.bak` など）を確認 |

## 実務Tips

### 文字コード・改行コード事故を防ぐ

- ファイルを開いたら、まず**右下の文字コード・改行コードを確認**する。既存ファイルは元の文字コードのまま保存するのが原則
- 本番サーバーに置く設定ファイル・シェルは、**LF・BOM なし**で保存されているか確認してから転送する
- 「機種依存文字」（丸数字・ローマ数字・`～` など）は SJIS と UTF-8 の変換で化けやすい。帳票や連携ファイルでは使わない
- 文字コードが混在したフォルダを Grep するときは、文字コードセットを変えて複数回検索する

### 置換を安全に行う

- 正規表現置換は、まず**「次を検索」で一致箇所を確認**してから「すべて置換」する
- 大きな置換の前にファイルをコピーしておく。特に Grep 置換は複数ファイルを一括で書き換えるため、必ずバックアップを取る
- 置換対象を「選択範囲」にすると、意図しない行の書き換えを防げる
- よく使う置換パターンはメモに残すか、マクロにして**手順を固定**する（人によって結果が変わらない）

### 作業効率を上げる

- Excel → サクラエディタ（タブ区切り）→ 正規表現で SQL・CSV・設定ファイルに変換、という流れは覚えておくと何度も使える
- ログ調査は「Grep で該当行を一覧 → ダブルクリックで前後を確認」が基本。結果ウィンドウ自体もテキストとして保存・加工できる
- 矩形選択は固定長データの列操作に強い。表示が崩れる場合は等幅フォントか確認する
- ソートと「選択行のマージ」を組み合わせると、IDの重複チェックや一覧の差分確認がすぐできる
- 複雑な加工（複数ファイルの集計、条件分岐が多い変換）はエディタで頑張らず、PowerShell や Python に切り替える

### チームで使うとき

- タイプ別設定・キー割り当て・マクロなどは、設定ダイアログの各タブにあるインポート / エクスポートで書き出して共有できる
- 社内標準の文字コード・改行コード・タブ幅を決め、タイプ別設定に反映しておく
