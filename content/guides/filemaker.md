# FileMaker 技術まとめ

## 基礎

Claris FileMaker（Claris は Apple の子会社）は、データベースと画面（レイアウト）とスクリプトを1つのファイルにまとめて作る、ローコード型の業務アプリ開発プラットフォームです。プログラミング経験が少なくても画面付きのアプリを作れ、**Windows・Mac・iPad・iPhone・Webブラウザ**から同じアプリを使えるのが特徴です。

### 主な用途

- 業務アプリの内製（受発注・在庫・日報・見積など）
- 顧客・案件管理
- iPad を使った現場業務（点検・検品・営業訪問。カメラやバーコード読み取りも使える）
- 小規模チームで共有するデータベース

### 製品構成

| 製品 | 役割 |
| --- | --- |
| FileMaker Pro | 開発ツール兼クライアント（Windows / Mac） |
| FileMaker Go | iPad / iPhone 用の無償クライアント |
| FileMaker Server | ファイルをホストして複数人で共有する。バックアップ・スケジュール実行・WebDirect・Data API を提供 |
| FileMaker Cloud | Claris が運用するクラウド版のサーバー |
| FileMaker WebDirect | Webブラウザからレイアウトをそのまま操作する仕組み（Server の機能） |

ファイルの拡張子は `.fmp12` です。

### まず押さえる用語

| 用語 | 意味 | 現場での注意点 |
| --- | --- | --- |
| テーブル | データの入れ物 | 1ファイルに複数テーブルを持てる |
| フィールド | 列。テキスト・数字・日付・時刻・タイムスタンプ・オブジェクト・計算・集計の型がある | 主キーはシリアル番号の自動入力か `Get ( UUID )` で作る |
| テーブルオカレンス（TO） | リレーションシップグラフ上のテーブルの「分身」 | 同じテーブルを用途別に複数のTOとして置ける。計算式やスクリプトは**TO名で**参照する |
| リレーションシップ | TO同士の結合条件 | 関連レコードの表示（ポータル）や集計の土台になる |
| レイアウト | 画面・帳票。1つのTOを基準に作る | どのTOを基準にしたかで、表示・検索できるデータが変わる |
| モード | ブラウズ（入力・閲覧）/ 検索 / レイアウト（画面編集）/ プレビュー（印刷確認） | 検索条件は検索モードで入力する |
| 対象レコード | 現在の検索結果の集合 | 多くのスクリプトステップは「対象レコード」に対して動く |
| アクセス権セット | アカウントごとの権限の組み合わせ | Data API や WebDirect などの「拡張アクセス権」もここで許可する |

## 環境構築

### 1. FileMaker Pro をインストールする

1. Claris のサイトから評価版、またはライセンス購入後のインストーラーを入手する
2. インストール時にライセンスキー（または Claris ID によるサインイン）を入力する
3. 起動後、`ファイル` メニューから新規ファイルを作成するか、スターターアプリから始める

### 2. 開発しやすい設定にする

- `ファイル → 管理 → データベース…` でテーブル・フィールド・リレーションシップを定義する
- `スクリプト → スクリプトワークスペース…` でスクリプトを作る
- `ツール → データビューア` で変数や式の値を確認し、`ツール → スクリプトデバッガ` でスクリプトをステップ実行する
- 初期状態のアカウント（`Admin` など）にはパスワードを設定し、`ファイル → 管理 → セキュリティ…` で利用者用のアカウントとアクセス権セットを作る

### 3. 複数人で共有する

| 方法 | 向いている場面 |
| --- | --- |
| FileMaker Server にアップロード | 業務で常時使う（推奨）。バックアップとスケジュール実行も使える |
| FileMaker Cloud | サーバーの管理をしたくない場合 |
| FileMaker Pro のネットワーク共有 | 一時的な検証のみ。同時接続数に制限があり、開いているPCを閉じると全員切断される |

FileMaker Server を使う場合の流れ:

1. サーバー機に FileMaker Server をインストールし、Admin Console（`https://サーバー名/admin-console`）にログインする
2. SSL 証明書を設定する（既定の自己署名証明書のままだとクライアントに警告が出る）
3. FileMaker Pro の `ファイル → 共有` にあるアップロード機能でファイルをサーバーへアップロードする（メニュー名はバージョンにより異なる）
4. クライアントは `ファイル → ホスト…` から接続する

ファイアウォールでは、FileMaker クライアントの通信に TCP 5003、Admin Console・WebDirect・Data API に TCP 443 を許可します。

ホストされるファイルの既定の保存場所は次のとおりです。

```text
Windows: C:\Program Files\FileMaker\FileMaker Server\Data\Databases\
macOS  : /Library/FileMaker Server/Data/Databases/
```

| キー | 動作 |

| `Ctrl+J` | 全レコードを表示 |

| `Ctrl+E` | レコード削除 |
| `Ctrl+T` | レコードを対象外にする |
| `Ctrl+R` | 最終検索条件を変更 |
| `Ctrl+S` | レコードのソート（保存ではない。FileMaker は自動保存） |
| `Ctrl+Shift+D` | データベースの管理 |
| `Ctrl+Shift+S` | スクリプトワークスペース |

### 検索モードの演算子

| 入力 | 意味 |
| --- | --- |
| `==山田` | 完全一致 |
| `山田` | 「山田」で始まる単語を含む |
| `*田*` | ワイルドカード（任意の文字列） |
| `=` | 空のフィールド |
| `*` | 何か入っているフィールド |
| `>=10000` / `<100` | 比較 |
| `2026/10/01...2026/10/31` | 範囲 |
| `//` | 今日 |
| `!` | 重複している値 |

複数の検索条件（`Ctrl+N` で追加）は **OR**、1つの検索条件内の複数フィールドは **AND** になります。「対象外」にチェックを入れた検索条件は除外条件になります。

### 計算式：基本

| 操作 | 構文 |
| --- | --- |
| 条件分岐 | `If ( 売上 >= 10000 ; "A" ; "B" )` |
| 多分岐 | `Case ( 区分 = 1 ; "個人" ; 区分 = 2 ; "法人" ; "その他" )` |
| 文字列結合 | `姓 & " " & 名` |
| 変数 | `Let ( [ 税率 = 0.1 ; 税 = Round ( 金額 * 税率 ; 0 ) ] ; 金額 + 税 )` |
| 空判定 | `IsEmpty ( 顧客::メール )` |
| 改行 | `"1行目¶2行目"`（`¶` は改行） |

引数の区切りは `;`（セミコロン）です。`,` を使うとエラーになります。

### 計算式：テキスト・数値・日付

| 操作 | 構文 |
| --- | --- |
| 部分抽出 | `Left ( テキスト ; 3 )` / `Middle ( テキスト ; 2 ; 3 )` / `Right ( テキスト ; 4 )` |
| 検索・置換 | `Position ( テキスト ; "-" ; 1 ; 1 )` / `Substitute ( テキスト ; "-" ; "" )` |
| 長さ・前後の空白 | `Length ( テキスト )` / `Trim ( テキスト )` |
| 全角・半角・かな | `Hankaku ( テキスト )` / `Zenkaku ( テキスト )` / `Hiragana ( テキスト )` / `Katakana ( テキスト )` |
| 型変換 | `GetAsNumber ( テキスト )` / `GetAsText ( 数値 )` / `GetAsDate ( "2026/10/19" )` |
| 丸め | `Round ( 金額 ; 0 )` / `Truncate ( 金額 ; 0 )` / `Int ( 数値 )` |
| 日付作成 | `Date ( 月 ; 日 ; 年 )`（例: `Date ( 10 ; 19 ; 2026 )`） |
| 月末日 | `Date ( Month ( 日付 ) + 1 ; 0 ; Year ( 日付 ) )` |
| 日付の分解 | `Year ( 日付 )` / `Month ( 日付 )` / `Day ( 日付 )` / `DayOfWeek ( 日付 )`（日曜=1） |
| 値一覧 | `ValueCount ( リスト )` / `GetValue ( リスト ; 2 )` |

### 計算式：Get 関数・リレーション・SQL

日本語版では Get 関数の引数が日本語で表示されます（カッコ内は英語版の名前）。

| 操作 | 構文 |
| --- | --- |
| 今日 | `Get ( 日付 )`（CurrentDate） |
| 対象レコード数 | `Get ( 対象レコード数 )`（FoundCount） |
| 直前のエラー | `Get ( 最終エラー )`（LastError） |
| スクリプト引数 | `Get ( スクリプト引数 )`（ScriptParameter） |
| ログイン中のアカウント | `Get ( アカウント名 )`（AccountName） |
| 一意なID | `Get ( UUID )` |
| 関連レコードの合計・件数 | `Sum ( 明細::金額 )` / `Count ( 明細::ID )` |
| 関連レコードの値一覧 | `List ( 明細::品名 )` |
| SQL で集計 | `ExecuteSQL ( "SELECT COUNT(*) FROM 顧客" ; "" ; "" )` |
| JSON | `JSONSetElement ( "{}" ; "id" ; 顧客::ID ; JSONNumber )` / `JSONGetElement ( $json ; "id" )` |

### FileMaker Server のコマンドライン（fmsadmin）

```powershell
fmsadmin list files -u admin -p "パスワード"        # ホスト中のファイル
fmsadmin list clients -u admin -p "パスワード"      # 接続中のクライアント
fmsadmin close "顧客管理.fmp12" -u admin -p "パスワード"   # ファイルを閉じる
fmsadmin open  "顧客管理.fmp12" -u admin -p "パスワード"   # ファイルを開く
fmsadmin help commands                               # コマンド一覧
```

詳しいオプションは `fmsadmin help <コマンド名>` で確認します。パスワードをバッチファイルに直書きしないよう注意します。

## サンプル

### 検索してエラーを処理するスクリプト

```text
# 有効な顧客を検索してソートする
エラー処理 [ オン ]
ウインドウの固定
レイアウト切り替え [ "顧客一覧" ]
検索モードに切り替え [ 一時停止: オフ ]
フィールド設定 [ 顧客::状態 ; "有効" ]
レコードを検索 [ ]
変数を設定 [ $err ; 値: Get ( 最終エラー ) ]
If [ $err = 401 ]
    カスタムダイアログを表示 [ "該当する顧客はありません。" ]
    全レコードを表示
    現在のスクリプト終了 [ テキスト結果: $err ]
Else If [ $err ≠ 0 ]
    カスタムダイアログを表示 [ "検索でエラーが発生しました: " & $err ]
    現在のスクリプト終了 [ テキスト結果: $err ]
End If
レコードのソート [ 記憶する ; ダイアログあり: オフ ]
```

`エラー処理 [ オン ]` にしないと、0件のときに FileMaker 標準のダイアログが出て利用者が操作に迷います。スクリプトステップの表示形式はバージョンによって多少異なります。

### 対象レコードを1件ずつ処理するループ

```text
エラー処理 [ オン ]
ウインドウの固定
レコード/検索条件/ページへ移動 [ 最初の ]
ループ
    フィールド設定 [ 顧客::ランク ; If ( 顧客::累計金額 >= 1000000 ; "A" ; "B" ) ]
    レコード/検索条件/ページへ移動 [ 次の ; 最後まできたら終了: オン ]
ループ終了
レコード/検索条件確定 [ ダイアログあり: オフ ]
```

全件に同じ値を入れるだけなら、`フィールド内容の全置換`（Replace Field Contents）のほうが簡単で速いこともあります。ただし元に戻せないため、実行前にバックアップを取ります。

### JSON で複数の引数を渡す

```text
# 呼び出し側
スクリプト実行 [ "請求書作成" ; 引数: JSONSetElement ( "{}" ;
    [ "customerId" ; 顧客::ID ; JSONNumber ] ;
    [ "month" ; "2026-10" ; JSONString ] ) ]

# 呼び出される側
変数を設定 [ $customerId ; 値: JSONGetElement ( Get ( スクリプト引数 ) ; "customerId" ) ]
変数を設定 [ $month ; 値: JSONGetElement ( Get ( スクリプト引数 ) ; "month" ) ]
```

改行区切りの引数より、項目名で取り出せる JSON のほうが、引数を増やしたときに壊れにくくなります。

### ExecuteSQL でリレーションなしに集計する

```text
ExecuteSQL (
  "SELECT SUM(\"金額\") FROM \"売上\" WHERE \"顧客ID\" = ? AND \"日付\" >= ?" ;
  "" ; "" ;
  顧客::ID ; Date ( 4 ; 1 ; 2026 )
)
```

- `FROM` に書くのは**テーブルオカレンス名**です
- 日本語や記号を含む名前は `\"...\"` で囲みます
- 値は `?` のプレースホルダで渡すと、日付の書式や `'` のエスケープを気にせずに済みます
- 使えるのは `SELECT` のみです。SQL に誤りがあると結果は `?` になります（データビューアで確認する）

### Data API で外部からレコードを取得する（curl）

アクセス権セットで拡張アクセス権 `fmrest` を有効にしてから使います。

```sh
# 1. ログインしてトークンを取得（レスポンスの response.token）
curl -X POST "https://fms.example.com/fmi/data/vLatest/databases/CustomerDB/sessions" \
  -H "Content-Type: application/json" -u "apiuser:password" -d '{}'

# 2. 検索
curl -X POST "https://fms.example.com/fmi/data/vLatest/databases/CustomerDB/layouts/api_customers/_find" \
  -H "Content-Type: application/json" -H "Authorization: Bearer <トークン>" \
  -d '{"query":[{"status":"active"}],"limit":"10"}'

# 3. ログアウト（トークンを破棄）
curl -X DELETE "https://fms.example.com/fmi/data/vLatest/databases/CustomerDB/sessions/<トークン>"
```

Data API 用には**必要なフィールドだけを置いた専用レイアウト**を作ります。ファイル名・レイアウト名に日本語を使う場合は URL エンコードが必要なため、API 用の名前は英数字にしておくと扱いやすくなります。

## エラー対応

### 主なエラーコード

スクリプトで `エラー処理 [ オン ]` にした後、`Get ( 最終エラー )` で番号を取得します。日本語版では日本語のメッセージが表示されます。

| 番号 | メッセージ（英語版） | 主な原因 | 対処 |
| --- | --- | --- | --- |
| 0 | No error | 正常 | — |
| 1 | User canceled action | 利用者がダイアログでキャンセルした | キャンセル時の分岐を用意する |
| 9 | Insufficient privileges | アクセス権セットで許可されていない操作 | アクセス権セットを確認する |
| 100 / 105 | File is missing / Layout is missing | 参照先のファイル・レイアウトが削除・改名された | スクリプトの指定先を確認する |
| 101 | Record is missing | 存在しないレコードへ移動しようとした | 対象レコード数を確認してから移動する |
| 102 | Field is missing | `フィールド設定` などで指定したフィールドがレイアウトのTOから参照できない | フィールドの指定とレイアウトの基準TOを確認する |
| 200 / 201 | Record access is denied / Field cannot be modified | レコード単位のアクセス権、計算フィールドなど変更できないフィールド | 権限設定・フィールドの種類を確認する |
| 301 | Record is in use by another user | 他のユーザーが同じレコードを編集中（ロック） | 時間をおいて再試行。編集後はすぐに確定する運用にする |
| 400 | Find criteria are empty | 検索条件が何も入っていない状態で検索した | 条件の入力を確認してから `レコードを検索` する |
| 401 | No records match the request | 検索結果が0件 | 0件時の分岐を用意する（上のサンプル参照） |
| 500 / 509 | Date value does not meet validation entry options / Field requires a valid value | 入力値の制限（入力値の制限オプション）に違反 | 入力値を見直すか、フィールドの入力値の制限を確認する |
| 504 | Value in field is not unique as required in validation entry options | 「ユニークな値」の制限に違反 | 重複データを確認する |
| 802 | Unable to open file | ファイルが開けない（使用中・破損・権限） | ファイルの場所とホスト状態を確認する |

### その他のよくあるトラブル

| 症状 | 主な原因 | 対処 |
| --- | --- | --- |
| 計算式の結果が `?` | `ExecuteSQL` の構文エラー、テーブルオカレンス名の誤り | データビューアで同じ式を評価し、名前と引用符を確認する |
| 関連フィールドが空で表示される | レイアウトの基準TOとリレーションシップの起点が違う | レイアウト設定の「レコードを表示するテーブル」と、リレーションシップグラフ上の経路を確認する |
| 検索で見つからない | 前方一致の単語検索、全角・半角の違い、索引設定 | `==` で完全一致、`*` でワイルドカードを使う。フィールドの索引の言語設定を確認する |
| サーバーに接続できない | ファイアウォール（TCP 5003）、ファイルが閉じている、SSL 証明書 | ポートとAdmin Console 上のファイル状態を確認。証明書を正式なものにする |
| 動作が遅い | 非保存の計算フィールドやサマリーをリスト表示、ネットワーク越しの大量レコード | 計算結果を保存する設計に変える、`サーバー上のスクリプト実行` で集計をサーバー側で行う |
| ファイルが破損した可能性がある | 強制終了、ホスト中のファイルを OS 側で直接コピー | 必ずバックアップから復元する。`ファイル → 修復…` は データ救出用で、修復後のファイルを本番に戻さない |

## 実務Tips

### 設計

- 主キーは**意味を持たない値**（シリアル番号の自動入力、または `Get ( UUID )`）にし、顧客コードなどの業務キーとは分ける
- リレーションシップグラフはTOが増えると読めなくなる。**アンカー・ブイ方式**などでTOの命名とグループ分けのルールを決める
- フィールド名・TO名・レイアウト名に「`開発用`」「`api_`」などの接頭辞を付け、用途を分かるようにする
- 非保存の計算フィールドや集計フィールドを一覧画面に多数置くと、件数が増えたときに急に遅くなる

### 運用・バックアップ

- ホスト中のファイルを**OS のコピーやバックアップソフトで直接コピーしない**。破損の原因になる。FileMaker Server のスケジュールバックアップを使い、その出力先をさらに別媒体へ退避する
- バックアップは毎日＋変更が多い時間帯の差分（プログレッシブバックアップ）を組み合わせる
- 大きな変更は本番ファイルで直接作業せず、コピーで検証してから反映する。スキーマ変更中は他のユーザーの操作がロックされることがある
- 年に一度などの節目に、**バックアップからの復元手順を実際に試す**

### セキュリティ

- 共有アカウント（全員が同じ `user` でログイン）をやめ、個人ごとのアカウントにする。`Get ( アカウント名 )` で更新者を記録できる
- `[完全アクセス]` 権限は管理者だけに付け、利用者には必要最小限のアクセス権セットを作る
- Data API・WebDirect・ODBC などの拡張アクセス権は、使うアカウントだけに有効にする
- SSL 証明書を正式なものにし、自己署名証明書の警告を利用者に「無視して接続」させる運用をしない

### チーム開発・保守

- スクリプトの先頭に `#` でコメント（目的・引数・戻り値）を書く
- 1つのスクリプトに処理を詰め込まず、`スクリプト実行` で部品化して JSON で引数を渡す
- 誰がいつ何を変えたか分かるよう、変更履歴（日付・内容・担当）をスクリプトのコメントや別紙に残す
- 作成者の退職で保守できなくなる例が多い。データベースデザインレポート（`ツール → データベースデザインレポート…`）を定期的に出力して残しておく
