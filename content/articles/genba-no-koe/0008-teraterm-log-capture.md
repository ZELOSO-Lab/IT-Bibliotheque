# 【Tera Term】「さっきのエラー、ログ残ってる？」に答えられなかった話と、ログを確実に・自動で取る設定手順

## 現場の声

> 組込み機器の評価で、シリアルコンソールを Tera Term でつないで試験していました。数時間に1回しか起きない異常終了が、ついに画面に出た瞬間、うれしくて先輩を呼びに行ったら、戻ってきたときには**画面が流れて消えていました**。
>
> 「ログ取ってたよね？」と聞かれて、取っていなかったことに気づきました。次の試験ではログを取ったものの、**いつ起きたのか時刻が分からない**、開くと `[0m` のような**謎の文字だらけ**、別の日のログで**上書き**……。結局、障害報告書に添付できるログが1つもありませんでした。

Tera Term のログは「ファイル → ログ」で取れますが、**取り忘れ・上書き・時刻なし**の3つで失敗しがちです。この記事では、ログ取得でハマるポイントと、接続した瞬間から自動でタイムスタンプ付きのログを残す設定手順を整理します。

## 前提の構成

| 項目 | 内容 |
| --- | --- |
| Tera Term | 5.x（4.x でもほぼ同じ。メニュー名が一部異なります） |
| 接続先 | Linux サーバー（SSH）、組込み機器（シリアル / COM ポート） |
| 用途 | ビルド・実行結果、gdb のデバッグ作業、機器の起動ログの記録 |

```text
C:\logs\teraterm\                          ← ログの保存先（英数字だけのパス）
├─ 20261012_093015_192.168.10.20.log       ← 接続日時_接続先 で自動命名
├─ 20261012_134502_COM3.log
└─ ...
```

C言語の開発では、ターゲット機器のシリアル出力や、サーバー上での gdb のやりとりを Tera Term 越しに見ることが多く、**ログがそのまま不具合の証拠**になります。

## ハマりどころ1：ログを取り忘れて、一度きりのエラーを逃す

**症状**

再現性の低いエラーが出たのに、ログを取っていなかった。

**原因**

「ファイル → ログ」は**手動で開始**する機能です。毎回の操作に頼る限り、いつか必ず取り忘れます。

**対処：接続と同時にログを自動で開始する設定にする。**（手順は後述の「自動ログ取得の設定」）

すでに取り忘れてしまった場合は、画面に残っている分だけでも救出します。

- 「編集 → すべて選択」→「編集 → コピー」でメモ帳などに貼り付ける
- 次にログを開始するときに、ログダイアログの「**現在のバッファを含める**」にチェックを入れると、画面とスクロールバッファに残っている内容もログの先頭に書き込まれます

スクロールバッファの行数は「設定 → ウィンドウ → スクロールバッファ」で増やせます。既定の 10000 行から、長時間の試験では 100000 行程度に増やしておくと救出できる範囲が広がります。

## ハマりどころ2：同じファイル名で上書きして、前のログが消える

**症状**

昨日のログが今日のログで上書きされていた。

**原因**

ログダイアログで毎回同じファイル名（既定の `teraterm.log`）のまま開始し、上書きの確認で「はい」を押していた。

**対処：ファイル名に日時と接続先を入れて、毎回別のファイルにする。**

Tera Term のログファイル名には、日時の書式と接続先の変数が使えます。

| 書式 | 意味 | 例 |
| --- | --- | --- |
| `%Y%m%d` | 年月日 | `20261012` |
| `%H%M%S` | 時分秒 | `093015` |
| `&h` | 接続先のホスト名（シリアルの場合は COM ポート名） | `192.168.10.20` / `COM3` |
| `&p` | ポート番号 | `22` |
| `&u` | ログインユーザー名 | `devuser` |

```text
%Y%m%d_%H%M%S_&h.log
→ 20261012_093015_192.168.10.20.log
```

同じファイルに追記したい場合は、ログダイアログで「**追記**」を選びます。

## ハマりどころ3：ログに時刻がなく、「いつ起きたか」が分からない

**症状**

ログにエラーは残っていたが、何時何分に起きたのか分からず、他の機器のログや試験記録と突き合わせられない。

**対処：「タイムスタンプ」を有効にする。**

ログダイアログ（または後述の自動ログ設定）で「タイムスタンプ」にチェックを入れると、各行の先頭に時刻が付きます（表示形式はバージョンや設定によって異なります）。

```text
[2026-10-12 13:45:01.123] boot: start
[2026-10-12 13:45:01.457] init: sensor ok
[2026-10-12 13:45:03.902] Segmentation fault (core dumped)
```

- タイムスタンプの種類（ローカル時刻 / UTC / ログ開始からの経過時間 / 接続からの経過時間）を選べます。障害調査で他のログと突き合わせるなら**ローカル時刻**、起動時間の計測なら**経過時間**が便利です。
- PC の時計がずれていると、記録された時刻もずれます。試験用 PC は時刻同期（Windows の「時刻を自動的に設定する」）を有効にしておきます。

## ハマりどころ4：ログが `[0m` や `[32m` だらけで読めない

**症状**

```text
[01;34msrc[0m  [01;32mavg[0m  avg.c
```

のような制御文字が混ざって、エディタで開くと読みにくい。

**原因**

Linux の `ls` の色付けやプロンプトの装飾は、**エスケープシーケンス**という制御文字で表現されています。画面では色として表示されますが、ログにはその文字列がそのまま記録されます。

**対処：ログダイアログで「プレーンテキスト」を有効にする。**

- 「プレーンテキスト」にチェックを入れると、エスケープシーケンスを取り除いた文字だけが記録されます。
- 「バイナリ」は受信したデータを**そのまま**保存するモードです。通信の生データを解析したいとき以外は使いません。

## ハマりどころ5：ログが文字化けする

**症状**

日本語のメッセージがログファイルで化ける。または画面の時点で化けている。

**原因**

原因は2か所に分かれます。

| どこで化けるか | 原因 | 対処 |
| --- | --- | --- |
| 画面の時点で化ける | 接続先の文字コード（UTF-8 / Shift_JIS / EUC-JP）と、Tera Term の受信設定が違う | 「設定 → 端末」の漢字コード（受信）を接続先に合わせる |
| 画面は正しく、ログだけ化ける | ログファイルの文字コードと、ログを開くエディタの文字コードが違う | Tera Term 5 のテキストログは既定で UTF-8 です。エディタを UTF-8 で開く |
| 画面が `ÿ` や記号だらけ（シリアル） | ボーレートなど通信設定の不一致 | 「設定 → シリアルポート」でボーレート・データ長・パリティ・ストップビットを機器の仕様に合わせる |

組込み機器のシリアル出力は `115200bps / 8bit / パリティなし / 1 ストップビット` が多いですが、**機器の仕様書で必ず確認**してください。

## ハマりどころ6：大事な場面がどこにあるか、ログの中で探せない

**症状**

数時間分のログの中から、「試験項目 No.15 を始めた時点」を探すのに時間がかかる。

**対処：試験の区切りでログにコメントを書き込む。**

- 「ファイル → ログ → ログにコメントを付加」（バージョンによって「コメントをログに追加」）で、任意の文字列をログに書き込めます。
- 「==== No.15 開始 電源再投入 ====」のように書いておくと、後で検索するだけでその場面に飛べます。
- 接続先に送信しない（コマンドとして実行されない）ので、機器の動作に影響しません。

## ハマりどころ7：ログを開いたままファイルを移動・削除できない、ログが巨大になる

**症状**

- 試験中のログを別フォルダに移そうとしたら「ファイルは使用中です」
- 1週間の連続試験で、ログが数 GB になってエディタで開けない

**対処**

- ログの中身を確認したいだけなら「ファイル → ログ → ログを表示」で開く（ログ取得は止まりません）
- ファイルを移動したいときは「ファイル → ログ → 閉じる」でログを終了してから
- 長時間試験は、TTL マクロの `logrotate` で一定サイズごとに別ファイルに切り替える（後述）

## 自動ログ取得の設定（手順）

ここからは、**接続した瞬間から、日時と接続先の名前付きで、タイムスタンプ付きのプレーンテキストログ**を自動保存する設定です。一度設定すれば、取り忘れはなくなります。

### 1. 保存先フォルダを作る

`C:\logs\teraterm\` のように、日本語・スペースを含まないパスに作ります。

### 2. ログの既定値を設定する

「設定 → その他の設定」を開き、「ログ」タブで次のように設定します（Tera Term 4.x では「設定 → その他の設定 → ログ」、一部の項目名が異なります）。

| 項目 | 設定値 |
| --- | --- |
| 標準のログファイル名 | `%Y%m%d_%H%M%S_&h.log` |
| ログ保存先フォルダ | `C:\logs\teraterm` |
| 自動的にログ採取を開始する | チェックを入れる |
| ログのオプション | プレーンテキスト・タイムスタンプにチェック、タイムスタンプの種類は「ローカル時刻」 |

### 3. 設定を保存する

「設定 → 設定の保存」で `TERATERM.INI` に上書き保存します。**これを忘れると、Tera Term を閉じた時点で設定が消えます。**

保存された `TERATERM.INI` には、次のような行が入ります（チームで設定を配布するときは、この部分をコピーしてもらうと早いです）。

```ini
LogDefaultName=%Y%m%d_%H%M%S_&h.log
LogDefaultPath=C:\logs\teraterm
LogAutoStart=on
LogTypePlainText=on
LogTimestamp=on
```

### 4. 動作を確認する

1. Tera Term を起動して接続する
2. 何かコマンドを実行する
3. `C:\logs\teraterm\` に `日時_接続先.log` ができ、中身に時刻付きで記録されていることを確認する

### 5. （応用）マクロでログ取得を自動化する

決まったサーバーに毎回つなぐ場合は、TTL マクロで「接続 → ログ開始 → ログイン後の定型コマンド」までまとめられます。

```text
; connect_with_log.ttl
; 接続先とログの保存先
host    = '192.168.10.20'
logdir  = 'C:\logs\teraterm\'

; ファイル名に日時を入れる
gettime timestr '%Y%m%d_%H%M%S'
sprintf2 logfile '%s%s_%s.log' logdir timestr host

; SSH で接続（パスワードは毎回入力させる）
sprintf2 cmd '%s:22 /ssh2 /auth=password /user=devuser /ask4passwd' host
connect cmd
if result <> 2 then
    messagebox 'Connection failed' 'error'
    end
endif

; ログ開始：バイナリ=0 追記=1 プレーンテキスト=1 タイムスタンプ=1
logopen logfile 0 1 1 1

; 試験の区切りをログに残す
logwrite '==== session start ===='#13#10

; 長時間試験用：10MB ごとに別ファイルに切り替え、古いものは 20 個まで残す
logrotate size 10485760
logrotate rotate 20
```

- `logopen` の引数は「ファイル名・バイナリ・追記・プレーンテキスト・タイムスタンプ」の順です。
- パスワードをマクロに直接書くのは避け、`/ask4passwd` で毎回入力するか、公開鍵認証（`/auth=publickey /keyfile=...`）を使います。
- マクロは `ttpmacro.exe connect_with_log.ttl` で実行するか、Tera Term の「コントロール → マクロ」から選びます。

## 補足：Tera Term 以外でもログを残す

Tera Term のログは「画面に表示されたもの」の記録です。サーバー上の作業そのものを残したい場合は、接続先でも記録できます。

```text
$ script -a -t 2> work.timing work.log    # 以降の端末操作をすべて work.log に記録（exit で終了）
```

```text
(gdb) set logging file gdb_session.log    # gdb の出力をファイルにも保存
(gdb) set logging enabled on              # gdb 12 以降。古い gdb では set logging on
```

gdb でのデバッグ手順は「gdb デバッグ」の記事で扱っています。Tera Term のログと gdb のログを両方残しておくと、後から報告書を書くときに困りません。

## チェックリスト

- [ ] 「自動的にログ採取を開始する」を有効にしている
- [ ] ログファイル名に日時（`%Y%m%d_%H%M%S`）と接続先（`&h`）が入っている
- [ ] 保存先は日本語・スペースを含まないフォルダ
- [ ] タイムスタンプを有効にしている
- [ ] プレーンテキストを有効にしている（生データが必要なときだけバイナリ）
- [ ] 「設定 → 設定の保存」で TERATERM.INI に保存した
- [ ] 接続先の文字コード・シリアル設定を合わせている
- [ ] スクロールバッファを長時間試験向けに増やしている
- [ ] 試験の区切りでログにコメントを残している
- [ ] 長時間試験では `logrotate` でファイルを分割している

## まとめ

- Tera Term のログは手動開始だと必ず取り忘れます。**自動ログ取得 + 日時入りファイル名**を最初に設定しておくのが一番の対策です。
- 障害調査で使えるログにするには、**タイムスタンプ**と**プレーンテキスト**の2つを有効にします。
- 設定は「設定の保存」で TERATERM.INI に書き込み、チームで同じ設定を共有すると、誰が試験しても同じ形式のログが残ります。

C言語の現場では、ログは「動いた」「落ちた」を証明する唯一の材料です。環境構築の段階で、ログ取得の設定まで済ませておきましょう。
