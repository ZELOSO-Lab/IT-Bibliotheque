# 【SQL】「SQL Developer が起動しない」から始まった導入で詰まった7つのことと、30分で接続まで終わらせる手順（Oracle SQL Developer）

## 現場の声

> 配属初日、「Oracle に SQL Developer でつないで、テーブル定義を確認しておいて」と言われました。ダウンロードページで**どれを落とせばいいか分からず**、適当に選んだ zip を展開したら「**JDK を指定してください**」と聞かれて手が止まりました。
>
> なんとか起動して接続情報を入れたら、今度は `ORA-12505` や `ORA-12514`。先輩からもらった接続情報は「ORCL」だけで、**それが SID なのかサービス名なのか**も分かりません。結局、テーブルを1つ開くまでに半日かかりました。

SQL Developer は**インストーラーがなく、zip を展開するだけ**で使えるツールです。手順自体は短いのですが、「どのファイルを選ぶか」「どこに展開するか」「接続情報の何を入れるか」の3点で迷うと、一気に時間を取られます。この記事では、導入でハマるポイントと、最初の接続までを最短で終わらせる手順を整理します。

接続設定の詳細（tnsnames.ora などの `.ora` ファイル）、初日にやっておく設定、便利なショートカットは、このシリーズの続きの記事で扱います。

## 前提の構成

| 項目 | 内容 |
| --- | --- |
| OS | Windows 10 / 11（64bit） |
| SQL Developer | 24.x（23.x 以前でもほぼ同じ。メニュー名が一部異なります） |
| 接続先 | Oracle Database 19c / 21c / 23ai（社内サーバーや検証用 VM） |
| Oracle Client | 不要（SQL Developer は JDBC Thin ドライバーを内蔵） |

```text
C:\tools\
└─ sqldeveloper\                ← zip を展開した場所（英数字だけのパス）
   ├─ sqldeveloper.exe          ← これを起動する
   ├─ sqldeveloper\bin\
   │   └─ sqldeveloper.conf     ← 起動オプション（言語・メモリ）
   └─ jdk\                      ← 「JDK 同梱版」ならここに JDK が入っている

C:\Users\<ユーザー名>\AppData\Roaming\SQL Developer\   ← 接続情報・設定の保存先
```

**SQL Developer 本体と、接続情報・設定は別の場所に保存される**、という点を最初に押さえておくと、バージョンアップや PC 移行で困りません。

## ハマりどころ1：ダウンロードページでどれを選べばいいか分からない

**症状**

ダウンロードページに「Windows 64-bit with JDK included」「Windows 32-bit/64-bit」「Mac OSX」「Linux RPM」「Other Platforms」と並んでいて、どれを選べばいいか分からない。

**原因**

違いは「**Java（JDK）が同梱されているかどうか**」だけです。SQL Developer は Java で動くアプリケーションなので、JDK 同梱版以外を選ぶと、別途 JDK を用意して場所を指定する必要があります。

**対処：Windows なら「Windows 64-bit with JDK included」を選ぶ。**

| 選択肢 | 中身 | 選ぶ場面 |
| --- | --- | --- |
| Windows 64-bit with JDK included | 本体 + 動作確認済みの JDK | **通常はこれ** |
| Windows 32-bit/64-bit | 本体のみ | 社内で JDK のバージョンが指定されている場合 |
| Other Platforms | 本体のみ（OS 共通） | Linux で RPM を使わない場合など |

- ダウンロードには **Oracle アカウント（無料）** でのサインインが必要です。会社のメールアドレスで作るか、社内に共有の手順があればそれに従います。
- ダウンロードした zip のバージョン番号（例：`sqldeveloper-24.3.1.347.1826-x64.zip`）は、後で問い合わせるときに必要になるので控えておきます。

## ハマりどころ2：「JDK のフルパスを指定してください」で止まる

**症状**

起動すると、`java.exe` の場所を聞くダイアログが出る。または、指定したら起動直後に落ちる。

**原因**

- JDK 同梱版ではない zip を選んだ
- 対応していないバージョンの Java（古い JRE や新しすぎる JDK）を指定した

**対処**

- いちばん早いのは、**JDK 同梱版を落とし直す**ことです。
- 別の JDK を使う場合は、SQL Developer のリリースノートに書かれている対応バージョン（24.x なら JDK 17 または 21）を指定します。指定するのは `java.exe` ではなく、**JDK のフォルダ**（例：`C:\Program Files\Java\jdk-17`）です。
- 一度間違った JDK を指定すると、次回以降もその設定で起動しようとします。指定し直すときは、次のファイルの `SetJavaHome` の行を書き換えるか、行ごと削除します。

```text
C:\Users\<ユーザー名>\AppData\Roaming\sqldeveloper\<バージョン>\product.conf

SetJavaHome C:\Program Files\Java\jdk-17
```

## ハマりどころ3：展開先によって起動しない・動作がおかしい

**症状**

- ダブルクリックしても何も起きない
- 起動はするが、拡張機能やドライバーの読み込みでエラーが出る

**原因**

- zip を**展開せずに**、エクスプローラーで zip の中を開いたまま `sqldeveloper.exe` を実行している
- 展開先のパスが長すぎる、または日本語・スペースを含む（例：`C:\Users\山田\デスクトップ\新しいフォルダー\`）
- `C:\Program Files\` 配下に展開し、書き込み権限がなくて設定が保存できない

**対処：`C:\tools\sqldeveloper\` のような、英数字だけの短いパスに展開する。**

- zip を右クリック →「すべて展開」で展開してから起動します。
- 展開後、`sqldeveloper.exe` を右クリック →「スタートにピン留めする」またはデスクトップにショートカットを作っておくと、毎回フォルダを探さずに済みます。
- 社内のセキュリティソフトがダウンロードした zip をブロックしている場合は、zip のプロパティで「許可する（ブロックの解除）」にチェックを入れてから展開します。

## ハマりどころ4：初回起動の「設定をインポートしますか？」で古い設定を引き継いで不具合

**症状**

2回目以降のインストール（バージョンアップ）で、初回起動時に「以前のバージョンから設定をインポートしますか？」と聞かれ、「はい」を選んだら動作が不安定になった。

**原因**

古いバージョンの設定や拡張機能の情報が、新しいバージョンと合わないことがあります。

**対処**

- **接続情報だけ引き継げればよい**なら、「いいえ」を選び、古いバージョンから接続をエクスポートして、新しいバージョンでインポートするほうが安全です（手順は「初日にやっておく設定」の記事で扱います）。
- 「はい」を選んで不具合が出た場合は、SQL Developer を終了し、`AppData\Roaming\SQL Developer\system<バージョン>` フォルダを別名に変えてから起動し直すと、まっさらな状態で起動できます。

## ハマりどころ5：SID とサービス名を取り違えて ORA-12505 / ORA-12514

**症状**

```text
接続テストに失敗しました:
ORA-12505, TNS:listener does not currently know of SID given in connect descriptor
```

```text
ORA-12514, TNS:listener does not currently know of service requested in connect descriptor
```

**原因**

接続ダイアログの「SID」と「サービス名」は**別のもの**です。

| 項目 | 意味 | 例 |
| --- | --- | --- |
| SID | データベースのインスタンス名（サーバー上で動いているプロセスの名前） | `ORCL` |
| サービス名 | リスナーに登録された、接続先の名前 | `orclpdb` / `orclpdb.example.co.jp` |

Oracle 12c 以降の**マルチテナント構成**では、実際にテーブルがあるのは **PDB（プラガブル・データベース）** で、PDB には**サービス名でしか接続できません**。「ORCL」という情報だけをもらって SID 欄に入れると、CDB（コンテナ）側に接続してしまい、目的のテーブルが見つからなかったり、ユーザーが存在しないと言われたりします。

**対処：接続情報は「ホスト・ポート・サービス名・ユーザー」の4点セットで確認する。**

- 接続情報をもらうときは「**SID ですか？ サービス名ですか？**」と必ず聞きます。
- DB サーバーにログインできる人がいれば、次のコマンドで登録されているサービス名を確認してもらえます。

```text
$ lsnrctl services        # リスナーに登録されているサービス名の一覧
$ lsnrctl status          # リスナーの状態と待ち受けポート
```

- SQL Developer の接続ダイアログでは、**「サービス名」を選んでから**値を入れます（既定は「SID」になっていることが多いので要注意です）。

## ハマりどころ6：接続テストで ORA-12541 / ORA-12170（そもそもサーバーに届かない）

**症状**

```text
ORA-12541: TNS:no listener
ORA-12170: TNS:Connect timeout occurred
IO Error: The Network Adapter could not establish the connection
```

**原因**

SID・サービス名の問題より手前で、**ネットワークとして DB サーバーに届いていない**状態です。

| エラー | よくある原因 |
| --- | --- |
| ORA-12541 / Network Adapter | ホスト名・IP の間違い、ポート番号の間違い（1521 以外を使っている）、リスナーが停止している |
| ORA-12170 / タイムアウト | ファイアウォールでポートが閉じている、VPN に接続していない、プロキシ環境 |

**対処：SQL Developer の外で、ポートが開いているかを先に確認する。**

```text
PS> Test-NetConnection 192.168.10.30 -Port 1521

TcpTestSucceeded : True     ← True ならネットワークは通っている
```

- `False` の場合は SQL Developer の設定をいくら変えてもつながりません。VPN・ファイアウォール・ポート番号を、インフラ担当や先輩に確認します。
- `True` なのに ORA-12514 / ORA-12505 が出る場合は、ハマりどころ5（サービス名）の問題です。

## ハマりどころ7：ORA-01017 / ORA-28000 / ORA-28001（ユーザー側の問題）

**症状**

ネットワークもサービス名も正しいのに、ログインで弾かれる。

**原因と対処**

| エラー | 意味 | 対処 |
| --- | --- | --- |
| ORA-01017 | ユーザー名またはパスワードが違う | 大文字・小文字を確認（11g 以降はパスワードの大小を区別）。Caps Lock も確認 |
| ORA-28000 | アカウントがロックされている | パスワードを何度も間違えるとロックされる。DBA にロック解除を依頼 |
| ORA-28001 | パスワードの有効期限切れ | SQL Developer では接続時にパスワード変更ダイアログが出る。出ない場合は DBA に依頼 |

- 共有の開発用ユーザーで何度もパスワードを間違えると、**チーム全員が接続できなくなります**。2回失敗したら、入力し直す前に接続情報を確認するのが安全です。
- `sys` ユーザーで接続する場合は、接続ダイアログの「ロール」を `SYSDBA` にします（通常の開発作業では使いません）。

## 30分で接続まで終わらせる手順

### 1. 接続情報を4点セットで揃える

作業を始める前に、次の情報を先輩や DBA から受け取ります。

| 項目 | 例 |
| --- | --- |
| ホスト名（または IP） | `dbsv01` / `192.168.10.30` |
| ポート | `1521` |
| **サービス名**（SID ではなく） | `orclpdb` |
| ユーザー名 / パスワード | `devuser` / （口頭や社内の手順で受け取る） |

### 2. ダウンロードして展開する

1. Oracle の SQL Developer ダウンロードページから「**Windows 64-bit with JDK included**」を選び、Oracle アカウントでサインインしてダウンロード
2. zip を右クリック →「すべて展開」で `C:\tools\` に展開
3. `C:\tools\sqldeveloper\sqldeveloper.exe` を起動
4. 初回起動の「設定のインポート」は、初めての導入なら「いいえ」

### 3. ネットワークを確認する

```text
PS> Test-NetConnection dbsv01 -Port 1521
```

`TcpTestSucceeded : True` を確認してから次に進みます。

### 4. 接続を作る

1. 左側の「接続」パネルで「＋」（新規接続）をクリック
2. 次のように入力する

| 項目 | 入力値 |
| --- | --- |
| 名前 | `DEV_devuser@orclpdb`（環境・ユーザー・接続先が分かる名前） |
| ユーザー名 / パスワード | `devuser` / ・・・ |
| パスワードの保存 | 個人 PC の開発環境ならチェック可。本番環境はチェックしない |
| 接続タイプ | 基本 |
| ホスト名 / ポート | `dbsv01` / `1521` |
| **サービス名** | `orclpdb`（SID ではなくサービス名を選ぶ） |

3. 「テスト」をクリックし、左下に「**ステータス：成功**」と出ることを確認
4. 「保存」→「接続」

### 5. 動作を確認する

SQL ワークシートで次の SQL を実行し、**自分がどこに、誰として接続しているか**を確認します。

```sql
SELECT SYS_CONTEXT('USERENV', 'CON_NAME')     AS con_name,     -- 接続しているPDB名
       SYS_CONTEXT('USERENV', 'SERVICE_NAME') AS service_name,
       USER                                   AS login_user
  FROM dual;
```

`CON_NAME` が `CDB$ROOT` になっていたら、PDB ではなくコンテナ側に接続しています。サービス名を見直してください。

### 補足：VS Code 派なら「SQL Developer for VS Code」もある

Oracle からは VS Code 用の拡張機能「SQL Developer for VS Code」も提供されています。普段のコーディングを VS Code で行っているなら選択肢になりますが、現場の手順書や先輩の操作説明は従来の SQL Developer（デスクトップ版）を前提にしていることが多いので、**まずはデスクトップ版を入れておく**のが無難です。

## まとめ

- SQL Developer は**zip を展開するだけ**で使えます。迷ったら「**JDK 同梱版**」を選び、**英数字だけの短いパス**に展開します。
- 接続エラーは「**ネットワーク（ORA-12541 / 12170）**」「**接続先の名前（ORA-12505 / 12514）**」「**ユーザー（ORA-01017 / 28000）**」の3段階に分けて切り分けると、原因に最短でたどり着けます。
- マルチテナント構成では、**SID ではなくサービス名**で PDB に接続します。接続情報は4点セットで受け取りましょう。

次の記事では、「TNS で接続して」と言われたときに必要になる **tnsnames.ora / sqlnet.ora などの `.ora` ファイルの中身**を扱います。
