# 【SQL】「コミットしたつもり」で他の人の作業を止めた話と、SQL Developer で初日にやっておく設定（Oracle）

## 現場の声

> テストデータを UPDATE して、結果を確認して、そのまま昼休みに行きました。戻ってきたら、隣の先輩が「**バッチが止まったまま動かない**」と困っていました。原因は、私の UPDATE が**コミットされずにロックを握ったまま**だったことです。
>
> その後も、日付の列に時刻が表示されず「**同じ日のデータなのに件数が合わない**」と悩んだり、開発環境のつもりで開いていたワークシートが**ステージング環境につながっていた**り。SQL Developer は入れただけで使えるぶん、**初期設定のままだと事故が起きやすい**ことを知りました。

SQL Developer は、インストール直後の設定のままでも SQL は実行できます。ただし、**コミットの扱い・日付の表示・NULL の見え方・接続先の見分け方**は、初日に設定しておかないと、気づかないうちにミスや他の人への迷惑につながります。この記事では、現場でハマるポイントと、初日にやっておく設定を整理します。

導入と最初の接続は「SQL Developer の導入」の記事、`.ora` ファイルは「tnsnames.ora / sqlnet.ora の中身」の記事で扱っています。

## 前提の構成

| 項目 | 内容 |
| --- | --- |
| SQL Developer | 24.x（23.x 以前でもほぼ同じ。メニュー名が一部異なります） |
| 接続先 | 開発（DEV）・ステージング（STG）・本番（PRD）の Oracle Database |
| 設定画面 | 「ツール → プリファレンス」（英語版は Tools → Preferences） |

```text
C:\tools\sqldeveloper\sqldeveloper\bin\sqldeveloper.conf   ← 起動オプション（表示言語など）
C:\Users\<ユーザー名>\AppData\Roaming\sqldeveloper\<バージョン>\product.conf
                                                             ← JDK の場所・メモリ
C:\Users\<ユーザー名>\AppData\Roaming\SQL Developer\       ← 接続情報・プリファレンス
```

この記事の設定は、ほぼすべて「**ツール → プリファレンス**」で行います。設定は OK を押した時点で保存されます。

## ハマりどころ1：コミット忘れでロックを握ったままにする

**症状**

- 自分が UPDATE した行を、他の人やバッチが更新しようとして**待たされ続ける**
- 自分の画面では更新後の値が見えているのに、他の人からは**更新前の値**が見える

**原因**

SQL Developer の**自動コミットは既定でオフ**です。INSERT / UPDATE / DELETE を実行しても、`COMMIT` するまでは自分のセッションの中だけの変更で、対象の行は**ロックされたまま**になります。

**対処：自動コミットはオフのまま、「実行したら必ずコミットかロールバック」を習慣にする。**

| 操作 | ショートカット |
| --- | --- |
| コミット | **F11** |
| ロールバック | **F12** |

- 自動コミットをオンにすると、間違えた UPDATE も**即座に確定**してしまい、取り消せなくなります。現場では**オフのまま使う**のが基本です（設定場所は「データベース → 拡張 → 自動コミット」）。
- 未コミットの変更がある状態で接続を切ったり SQL Developer を閉じたりすると、「コミットしますか？ロールバックしますか？」と聞かれます。**内容を思い出せないなら「ロールバック」**を選びます。
- 長時間席を離れる前は、F11 か F12 のどちらかを押してから離れます。

**注意：DDL は自動でコミットされる**

`CREATE TABLE` や `ALTER TABLE`、`TRUNCATE` などの DDL を実行すると、Oracle はその前に**未コミットの変更を自動でコミット**します。「UPDATE して確認してからロールバックするつもりが、途中で `CREATE TABLE` を実行して確定してしまった」という事故はよく起きます。DML の確認中に DDL を混ぜないようにします。

## ハマりどころ2：日付に時刻が表示されず、件数が合わない

**症状**

```text
CREATED_AT
----------
26-10-12
26-10-12
```

同じ日付に見えるのに、`WHERE created_at = DATE '2026-10-12'` で1件も取れない。

**原因**

Oracle の `DATE` 型は**時刻（時分秒）まで持っています**。SQL Developer の既定の日付書式（日本語環境では `RR-MM-DD` など）では時刻が表示されないため、`2026-10-12 09:15:30` のデータが `26-10-12` と表示されています。

**対処：NLS の日付書式を、時刻まで表示する形にする。**

「ツール → プリファレンス → データベース → NLS」で次のように設定します。

| 項目 | 設定値 |
| --- | --- |
| 日付書式 | `YYYY-MM-DD HH24:MI:SS` |
| タイムスタンプ書式 | `YYYY-MM-DD HH24:MI:SS.FF3` |
| タイムスタンプTZ書式 | `YYYY-MM-DD HH24:MI:SS.FF3 TZH:TZM` |

- 表示が変わるだけで、データそのものは変わりません。
- 日付で絞り込むときは、時刻を含めて範囲で指定します。

```sql
SELECT *
  FROM orders
 WHERE created_at >= DATE '2026-10-12'
   AND created_at <  DATE '2026-10-13';   -- 10/12 の 00:00:00 〜 23:59:59
```

- SQL の中で `TO_CHAR(created_at)` のように**書式を省略して変換している**と、この設定や接続先の設定によって結果が変わります。アプリや手順書の SQL では、`TO_CHAR(created_at, 'YYYY-MM-DD HH24:MI:SS')` のように書式を必ず書きます。

## ハマりどころ3：NULL と空白・文字列の "null" の区別がつかない

**症状**

グリッドで空欄に見えるセルが、NULL なのか、スペースなのか分からない。`WHERE col = ''` で検索しても取れない。

**原因**

- 既定では NULL は `(null)` と表示されますが、設定やバージョンによっては**空欄**に見えることがあります。
- Oracle では**空文字 `''` は NULL として扱われる**ため、`col = ''` は常に偽です。NULL の検索は `IS NULL` を使います。

**対処：NULL を目立つ表示にする。**

「ツール → プリファレンス → データベース → 拡張」で次のように設定します。

| 項目 | 設定値 |
| --- | --- |
| NULL値の表示 | `(null)` |
| 背景色を使用してNULLを表示 | チェックを入れ、薄い黄色など目立つ色を選ぶ |

これで、NULL・スペース・文字列の `'null'` が見た目で区別できます。

## ハマりどころ4：本番環境と開発環境を取り違える

**症状**

開発環境で実行するつもりの DELETE を、別のワークシート（ステージングや本番に接続中）で実行しそうになった。

**原因**

SQL Developer は複数の接続を同時に開けるため、**今どのワークシートがどの接続か**が分かりにくくなります。

**対処：接続名・色・パスワード保存の3つで、本番を目立たせる。**

1. **接続名の先頭に環境名を付ける**：`DEV_devuser@orclpdb`、`STG_...`、`PRD_...`。ワークシートのタブにも接続名が表示されます。
2. **接続に色を付ける**：接続のプロパティ（バージョンによっては接続ダイアログの「色」）で、本番接続を赤にすると、その接続のワークシートの枠に色が付きます。
3. **本番接続ではパスワードを保存しない**：接続するたびにパスワードを入力することで、「本番につなぐ」という操作を意識できます。

さらに、本番では原則として**参照専用ユーザー**で接続し、更新が必要な作業は手順書とダブルチェックで行う運用にしておくと、取り違えても被害が出ません。

## ハマりどころ5：結果が50行しか取れず、全件だと思い込む

**症状**

グリッドに50行しか表示されず、それが全件だと思って報告してしまった。

**原因**

SQL Developer は大量のデータを一度に取らないよう、**最初の数十行だけを取得**し、スクロールすると続きを取りに行きます（取得件数は「データベース → 拡張 → SQL配列のフェッチ・サイズ」、最大 200）。

**対処**

- 件数を知りたいときは、**`SELECT COUNT(*)`** を別に実行します。
- グリッドを右クリック →「行数のカウント」でも件数を確認できます。
- グリッドを一番下までスクロールすると、追加で取得されていきます（大きなテーブルでは時間がかかります）。
- 全件を CSV などに出力したいときは、グリッドで右クリック →「エクスポート」を使います（エクスポートは画面の表示件数に関係なく全件を出力します）。

## ハマりどころ6：コードが読みにくい・行番号が出ない・文字化けする

**症状**

- エラーで「行 37」と言われても、行番号が出ていないので探せない
- 文字が小さい
- 日本語を含む SQL ファイルを開いたら文字化けした

**対処：コードエディタの表示とエンコーディングを設定する。**

| 設定場所（ツール → プリファレンス） | 項目 | 設定値 |
| --- | --- | --- |
| コード・エディタ → 行ガター | 行番号の表示 | チェックを入れる |
| コード・エディタ → フォント | フォント名 / サイズ | `Consolas` や `MS ゴシック` など等幅フォント / 14 前後 |
| 環境 | エンコーディング | `UTF-8`（チームの SQL ファイルが Shift_JIS ならそれに合わせる） |

- 表示言語を英語にしたい場合（英語の情報を検索しやすくするため、あえて英語にする人もいます）は、`sqldeveloper.conf` に次の行を追加して再起動します。

```text
AddVMOption -Duser.language=en
```

- 大きな結果やたくさんのワークシートで動作が重いときは、`product.conf` でメモリの上限を増やせます。

```text
AddVMOption -Xmx2048m
```

## ハマりどころ7：PC を替えたら接続設定がすべて消えた

**症状**

PC の入れ替えや SQL Developer のバージョンアップで、何十個もあった接続を作り直すことになった。

**原因**

接続情報は SQL Developer 本体のフォルダではなく、`AppData\Roaming\SQL Developer\` に保存されています。本体だけを新しくしても、接続情報は移りません。

**対処：接続をエクスポートしておく。**

1. 「接続」パネルの「Oracle接続」を右クリック →「**接続のエクスポート**」
2. 出力する接続を選び、ファイル（JSON）の保存先を指定
3. パスワードも含める場合は「**パスワードの暗号化に使用するキー**」を指定する（キーを忘れるとパスワードは復元できません）
4. 新しい環境では「Oracle接続」を右クリック →「接続のインポート」で読み込む

チームで共通の接続一覧（パスワードなし）をエクスポートして共有しておくと、新しく参加した人の初日の作業が数分で終わります。

## 初日にやっておく設定（まとめ）

「ツール → プリファレンス」で、上から順に設定します。

| 設定場所 | 項目 | 設定値 | 目的 |
| --- | --- | --- | --- |
| データベース → 拡張 | 自動コミット | **オフ**（既定のまま） | 間違えた更新を取り消せるようにする |
| データベース → 拡張 | NULL値の表示 / 背景色 | `(null)` / 色を付ける | NULL を見分ける |
| データベース → NLS | 日付書式 | `YYYY-MM-DD HH24:MI:SS` | 時刻まで表示する |
| データベース → NLS | タイムスタンプ書式 | `YYYY-MM-DD HH24:MI:SS.FF3` | ミリ秒まで表示する |
| データベース → 拡張 | Tnsnames ディレクトリ | `C:\oracle\network\admin` | TNS 接続を使う場合 |
| コード・エディタ → 行ガター | 行番号の表示 | オン | エラー行を探す |
| コード・エディタ → フォント | フォント / サイズ | 等幅 / 14 前後 | 読みやすくする |
| 環境 | エンコーディング | UTF-8（チームに合わせる） | 文字化けを防ぐ |

接続ごとに、次の3つを設定します。

- 接続名の先頭に `DEV_` / `STG_` / `PRD_`
- 本番接続は色を赤に
- 本番接続はパスワードを保存しない

最後に、接続をエクスポートしてバックアップしておきます。

## チェックリスト

- [ ] 自動コミットがオフになっていることを確認した
- [ ] UPDATE / DELETE の後は F11（コミット）か F12（ロールバック）を押している
- [ ] DML の確認中に DDL を実行していない
- [ ] 日付書式を `YYYY-MM-DD HH24:MI:SS` にした
- [ ] NULL を背景色付きで表示する設定にした
- [ ] 接続名に環境名（DEV / STG / PRD）を付けた
- [ ] 本番接続に色を付け、パスワードを保存していない
- [ ] 件数は `COUNT(*)` で確認している（グリッドの行数を全件と思い込まない）
- [ ] 行番号を表示し、エンコーディングをチームに合わせた
- [ ] 接続をエクスポートしてバックアップした

## まとめ

- SQL Developer の**自動コミットは既定でオフ**です。更新したら **F11 / F12** で必ず確定か取り消しをし、ロックを握ったまま席を離れないようにします。
- **日付書式と NULL の表示**を初日に変えておくだけで、「件数が合わない」「空欄の正体が分からない」といった調査の時間が大きく減ります。
- **接続名・色・パスワード保存**で本番を目立たせ、接続はエクスポートしてバックアップしておきましょう。
