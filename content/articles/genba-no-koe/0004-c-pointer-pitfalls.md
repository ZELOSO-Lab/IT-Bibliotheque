# 【C言語】「*」と「&」が読めなくて既存コードの改修が止まった話と、ポインタでハマる8つの勘違い

## 現場の声

> 「この関数の戻り値を1つ増やしてほしいだけです」
>
> 既存の C言語のソースを開くと、`int get_data(char **out, size_t *len)` という関数。中では `*out = buf;`、`(*len)++;` と書かれていて、呼び出し元では `get_data(&p, &n);`。
>
> 「`*` が付いたり `&` が付いたり、`**` って何？」と調べ始めて半日。ようやく修正して動かしたら、今度は `Segmentation fault`。原因は、関数の中で引数のポインタ変数に代入しても、**呼び出し元には何も返っていなかった**ことでした。

ポインタは「アドレスを入れる変数」と覚えるだけでは、実際のコードは読めません。この記事では、現場で既存コードを読むとき・直すときに引っかかる勘違いを、1つずつほどいていきます。

## まず確認：ポインタは「住所を書いたメモ」

```c
int  value = 10;      /* int の値を入れる箱 */
int *p     = &value;  /* 「value の住所」を入れる箱 */
```

```text
 アドレス      中身
 0x1000  ┌──────────┐
 value   │    10    │
         └──────────┘
 0x2000  ┌──────────┐
 p       │  0x1000  │ ──→ value を指している
         └──────────┘
```

| 書き方 | 読み方 | 上の例での値 |
| --- | --- | --- |
| `&value` | value の**住所** | `0x1000` |
| `p` | p に書いてある住所 | `0x1000` |
| `*p` | p に書いてある住所の**中身** | `10` |
| `&p` | p 自身の住所 | `0x2000` |

覚えることは「`&` は住所を取る、`*` は住所をたどる」の2つだけです。ただし、`*` は**宣言のとき**と**式の中**で意味が変わるのが最初の落とし穴です。

## ハマりどころ1：宣言の「*」と式の「*」を同じものだと思う

**症状**

`int *p = &value;` と `*p = 20;` の `*` が同じ意味に見えて混乱する。

**原因**

- 宣言の `int *p` は「p は int へのポインタ型」という**型の指定**
- 式の `*p` は「p が指す先をたどる」という**演算**

`int *p = &value;` は「`*p` に `&value` を入れる」ではなく、「ポインタ `p` を宣言して、`&value` で初期化する」という意味です。

**対処：宣言は「型」と「名前」に分けて読む。**

```c
int *p = &value;   /* 型: int*  名前: p  初期値: &value */
*p = 20;           /* 式: p の指す先（= value）に 20 を代入 */
```

さらに次の書き方にも注意が必要です。

```c
int* a, b;   /* a は int*、b は int（ポインタではない） */
int *a, *b;  /* 両方ポインタにするならそれぞれに * を付ける */
```

`*` は変数名側に付くので、**1行に1変数ずつ宣言する**のが安全です。

## ハマりどころ2：関数でポインタ変数に代入しても、呼び出し元は変わらない

**症状**

関数の中で `malloc` して引数に入れたのに、呼び出し元では `NULL` のまま。

**原因**

C言語の引数は**すべて値渡し（コピー）**です。ポインタを渡しても、渡されるのは「住所のコピー」です。関数の中でそのコピーを書き換えても、呼び出し元の変数は変わりません。

```c
/* NG：p はコピーなので、呼び出し元の buf は NULL のまま */
void alloc_buffer(char *p)
{
    p = malloc(100);
}

char *buf = NULL;
alloc_buffer(buf);
strcpy(buf, "abc");   /* NULL に書き込んで Segmentation fault */
```

**対処：呼び出し元の「ポインタ変数そのもの」を書き換えたいときは、そのポインタの住所（ポインタへのポインタ）を渡す。**

```c
/* OK：char ** で受け取り、*out に代入する */
int alloc_buffer(char **out, size_t size)
{
    char *p = malloc(size);
    if (p == NULL) return -1;
    *out = p;             /* 呼び出し元の buf そのものを書き換える */
    return 0;
}

char *buf = NULL;
if (alloc_buffer(&buf, 100) == 0) {
    strcpy(buf, "abc");
    free(buf);
}
```

冒頭の `get_data(char **out, size_t *len)` も同じ考え方です。「呼び出し元の変数を書き換えたい」ときは、**その変数の型に `*` を1つ足した型**で受け取り、呼び出し側で `&` を付けます。

| 書き換えたい変数の型 | 関数の引数の型 | 呼び出し方 |
| --- | --- | --- |
| `int n` | `int *` | `func(&n)` |
| `char *p` | `char **` | `func(&p)` |
| `Item *item` | `Item **` | `func(&item)` |

## ハマりどころ3：配列とポインタを同じものだと思う

**症状**

関数の中で `sizeof(arr)` が配列のサイズにならない。

**原因**

配列は、ほとんどの式の中で「先頭要素へのポインタ」に自動変換されます。関数の引数に配列を渡したときも同じで、**受け取った側にはポインタしか届きません**。

```c
void print_size(int arr[])        /* 実際には int *arr と同じ */
{
    printf("%zu\n", sizeof(arr)); /* ポインタのサイズ（8 など）になる */
}

int data[10];
printf("%zu\n", sizeof(data));    /* 40（int が4バイトの場合） */
print_size(data);                 /* 8 */
```

gcc はこのミスを既定で警告してくれます（`warning: 'sizeof' on array function parameter 'arr' will return size of 'int *'`）。`sizeof` で型・配列・構造体のサイズを調べる方法は「[変数のサイズを知りたいときは sizeof におまかせ](/articles/c-sizeof-variable-size)」を参照してください。

**対処：配列を渡すときは、要素数も一緒に渡す。**

```c
#define ARRAY_SIZE(a) (sizeof(a) / sizeof((a)[0]))

void print_all(const int *arr, size_t count)
{
    for (size_t i = 0; i < count; i++) {
        printf("%d\n", arr[i]);
    }
}

int data[10] = {0};
print_all(data, ARRAY_SIZE(data));
```

`ARRAY_SIZE` マクロは**配列を宣言したスコープの中でだけ**正しく使えます。ポインタに対して使うと誤った値になる点に注意してください。

## ハマりどころ4：初期化していないポインタ・NULL ポインタを使う

**症状**

`Segmentation fault`。または、たまたま別の変数を書き換えて、離れた場所で値がおかしくなる。

**原因**

```c
int *p;          /* 中身は不定（どこを指しているか分からない） */
*p = 10;         /* 不定の住所に書き込む */

char *name = NULL;
printf("%zu\n", strlen(name));   /* NULL をたどる */
```

**対処**

- ポインタは**宣言と同時に初期化**する（指す先がまだないなら `NULL`）
- 外部から受け取ったポインタは、使う前に `NULL` チェックする
- `-Wall` を付けると、初期化前の使用（`-Wmaybe-uninitialized`）の多くを警告してくれます

```c
int process(const char *name)
{
    if (name == NULL) return -1;
    /* ... */
    return 0;
}
```

## ハマりどころ5：文字列リテラルを書き換えようとする

**症状**

```c
char *msg = "hello";
msg[0] = 'H';          /* Segmentation fault */
```

**原因**

`"hello"` は読み取り専用領域に置かれた文字列です。`char *msg` はその住所を持っているだけなので、書き換えると落ちます。一方、配列として宣言すると、**中身がスタックにコピー**されるので書き換えられます。

```c
char  msg1[] = "hello";   /* 6バイトの配列にコピー：書き換え OK */
char *msg2   = "hello";   /* 読み取り専用領域を指すだけ：書き換え NG */
```

**対処：文字列リテラルを指すポインタには `const` を付ける。**

```c
const char *msg = "hello";
msg[0] = 'H';    /* コンパイルエラーになるので、実行前に気づける */
```

## ハマりどころ6：ポインタの足し算が「1バイト」ずつだと思う

**症状**

バイナリデータを読む処理で、`p + 4` が4バイト先ではなく16バイト先を指していた。

**原因**

ポインタに `+1` すると、**指している型のサイズ分**進みます。

```c
int  nums[4] = {10, 20, 30, 40};
int *p = nums;

printf("%d\n", *(p + 1));    /* 20：p + 1 は sizeof(int) バイト先 */
printf("%d\n", p[1]);        /* 20：p[1] は *(p + 1) と同じ意味 */
```

**対処：バイト単位で進めたいときは `unsigned char *` で扱う。**

```c
const unsigned char *bytes = (const unsigned char *)buffer;
uint32_t len;
memcpy(&len, bytes + 4, sizeof len);   /* 先頭から4バイト目の位置を読む */
```

`*(uint32_t *)(bytes + 4)` のように型を変換して直接読むと、CPU によってはアライメント違反で落ちます。`memcpy` で読み出すのが安全です。

## ハマりどころ7：const の位置で意味が変わる

**症状**

関数の引数に `const` が付いていて、何が変更禁止なのか分からない。

**原因**

`const` は**すぐ左にあるもの**（左に何もなければすぐ右）を変更禁止にします。

| 宣言 | 指す先の中身を変更 | ポインタ自体を変更 |
| --- | --- | --- |
| `const char *p` | できない | できる |
| `char const *p` | できない（上と同じ） | できる |
| `char *const p` | できる | できない |
| `const char *const p` | できない | できない |

**対処：関数の引数で「読むだけ」のポインタには `const char *` を付ける。**

```c
size_t count_char(const char *str, char target);   /* str の中身は書き換えない、という約束 */
```

呼び出し側から見て「この関数に渡しても中身は壊されない」ことが型で分かります。既存コードを読むときも、`const` の有無が「この引数は出力用か入力用か」の大きなヒントになります。

## ハマりどころ8：関数ポインタの宣言が読めない

**症状**

```c
void (*handler)(int);
int (*compare)(const void *, const void *);
```

のような宣言で手が止まる。

**原因**

関数ポインタは「関数の住所」を入れる変数です。`(*名前)` の括弧が必須で、これがないと「ポインタを返す関数の宣言」になってしまいます。

```c
int *f(int);      /* int* を返す関数 f の宣言 */
int (*f)(int);    /* int を返す関数へのポインタ f */
```

**対処：typedef で名前を付けて読む。**

```c
/* 「int を受け取り void を返す関数」の型に名前を付ける */
typedef void (*EventHandler)(int code);

void on_error(int code)   { printf("error: %d\n", code); }
void on_success(int code) { printf("ok: %d\n", code); }

void run(EventHandler handler, int code)
{
    if (handler != NULL) {
        handler(code);       /* (*handler)(code) と書いても同じ */
    }
}

run(on_error, 500);
run(on_success, 200);
```

標準ライブラリの `qsort` も関数ポインタを受け取ります。比較関数の書き方は「構造体配列」の記事で扱います。

## 既存コードを読むときの手順

1. **宣言を右から左へ読む**：`char **out` →「out は、char へのポインタ、へのポインタ」
2. **呼び出し側の `&` を探す**：`func(&x)` なら、関数は `x` を書き換える可能性がある
3. **`const` の有無で入出力を判断する**：`const` 付きは入力、なしは出力（または両方）
4. **`malloc` している関数を確認する**：戻り値や `**` 引数で返された領域を、誰が `free` するかを確認する
5. **分からない宣言は typedef に置き換えて読む**：関数ポインタや配列へのポインタは、型に名前を付けると一気に読みやすくなる
6. **gdb で実際の値を見る**：`print p`、`print *p`、`print p[0]@5` で、住所と中身を確認する（gdb の記事で詳しく扱います）

## チェックリスト

- [ ] ポインタは宣言と同時に初期化している（なければ `NULL`）
- [ ] 1行に1変数ずつ宣言している
- [ ] 呼び出し元のポインタを書き換える関数は `**` で受け取っている
- [ ] 配列を関数に渡すときは要素数も渡している
- [ ] 外部から受け取ったポインタは `NULL` チェックしている
- [ ] 文字列リテラルは `const char *` で受けている
- [ ] 読むだけの引数には `const` を付けている
- [ ] バイト単位のアクセスは `unsigned char *` と `memcpy` で行っている
- [ ] 関数ポインタは typedef で型名を付けている
- [ ] `-Wall -Wextra` の警告がゼロ

## まとめ

- ポインタは「住所を書いたメモ」。`&` で住所を取り、`*` で住所をたどります。
- C言語の引数は**すべて値渡し**です。呼び出し元の変数を書き換えたいときは、その変数の住所を渡します。
- 配列は関数に渡した時点でポインタになり、要素数の情報が消えます。要素数は別の引数で渡します。
- `const` と typedef を使うと、ポインタの「役割」がコードに表れ、読む人も書く人も迷わなくなります。
