# 【SQL】「毎回マウスで実行ボタン」を卒業した話と、SQL Developer の便利なショートカットと機能（Oracle）

## 現場の声

> 調査のたびに SQL を書いて、マウスで「実行」ボタンを押して、結果をコピーして Excel に貼る……を繰り返していました。ある日、隣で作業を見ていた先輩が、**キーボードだけで SQL を整形し、結果を CSV にして、さっき実行した SQL を履歴から呼び出す**のを見て、作業スピードが倍以上違うことに気づきました。
>
> しかも私は、ワークシートに SQL を何本も並べて実行したときに、**カーソルの位置によって別の SQL が実行されていた**ことにも気づいていませんでした。

SQL Developer は機能が多いぶん、**知らないと一生使わない便利機能**がたくさんあります。この記事では、現場で手が止まりがちな場面と、それを解決するショートカット・機能を整理します。最後に早見表をまとめています。

導入・`.ora` ファイル・初日の設定は、このシリーズの前の記事で扱っています。

## 前提の構成

| 項目 | 内容 |
| --- | --- |
| SQL Developer | 24.x（Windows・既定のキー割り当て） |
| 接続先 | Oracle Database 19c / 21c / 23ai |
| 主な作業 | 調査用の SELECT、テストデータの作成、結果の共有 |

ショートカットは、バージョンや「キーボード・スキーム」の設定によって異なる場合があります。自分の環境で何が割り当てられているかは、「**ツール → プリファレンス → ショートカット・キー**」で検索して確認・変更できます。

## 手が止まる場面1：別の SQL が実行される・結果の出方が違う

**症状**

- ワークシートに SQL を何本か並べて実行したら、意図しない SQL が実行された
- 同じ SQL なのに、表形式（グリッド）で出るときと、テキストで出るときがある

**原因**

SQL Developer には実行方法が2種類あり、動きが違います。

| 実行方法 | ショートカット | 何を実行するか | 結果の出方 |
| --- | --- | --- | --- |
| **文の実行** | **Ctrl+Enter**（F9） | カーソルがある位置の **1文だけ** | 「問合せ結果」タブにグリッドで表示 |
| **スクリプトの実行** | **F5** | ワークシートの **すべての文を上から順に** | 「スクリプト出力」タブにテキストで表示 |

「文の実行」は、カーソル位置の文を**空行やセミコロンで区切って**判断します。SQL の間に空行がないと、前後の SQL がつながって1文として扱われ、エラーや意図しない実行になります。

**対処**

- SQL と SQL の間には、**セミコロンと空行**を必ず入れる
- 確実に実行範囲を指定したいときは、**範囲を選択してから Ctrl+Enter**（選択した部分だけが実行される）
- UPDATE / DELETE を含むワークシートで F5 を押すと**全部が実行される**ため、更新系の SQL は別のワークシートに分けておく

```sql
-- 1本目
SELECT COUNT(*) FROM orders WHERE status = 'NEW';

-- 2本目（空行で区切る）
SELECT * FROM orders WHERE status = 'NEW' ORDER BY created_at DESC;
```

## 手が止まる場面2：長い SQL が読めない・書くのが遅い

**症状**

他の人から受け取った1行の長い SQL が読めない。テーブル名・列名を毎回調べて手で打っている。

**対処：整形・補完・大文字小文字変換・コメント切り替えを使う。**

| 操作 | ショートカット |
| --- | --- |
| SQL を整形する | **Ctrl+F7** |
| 補完（テーブル名・列名の候補を出す） | **Ctrl+Space** |
| 大文字 / 小文字 / 先頭だけ大文字を切り替える | **Ctrl+'**（押すたびに切り替わる） |
| 選択行をコメントにする / 戻す | **Ctrl+/** |
| テーブルの定義をポップアップで見る | テーブル名にカーソルを置いて **Shift+F4** |

- 整形のルール（キーワードを大文字にする、カンマを行頭に置くなど）は、「ツール → プリファレンス → コード・エディタ → フォーマット」で変更できます。チームで同じ設定をエクスポートして共有すると、レビューで差分が読みやすくなります。
- テーブル名を入力して `.`（ドット）を打つと、列名の候補が自動で出ます。テーブルに別名（`o` など）を付けた場合も、`o.` で候補が出ます。
- 左の接続ツリーから、テーブルを**ワークシートにドラッグ＆ドロップ**すると、全列を並べた SELECT 文や INSERT 文を自動で作れます。

## 手が止まる場面3：さっき実行した SQL をもう一度書いている

**症状**

昨日実行した調査用 SQL をもう一度使いたいが、保存していなかった。ワークシートを閉じてしまった。

**対処：SQL 履歴を使う。**

| 操作 | ショートカット |
| --- | --- |
| SQL 履歴の一覧を開く | **F8** |
| 直前 / 直後に実行した SQL をワークシートに呼び出す | **Ctrl+↑ / Ctrl+↓** |

- 履歴の一覧では、キーワードで絞り込み、ダブルクリックでワークシートに戻せます。履歴は接続を切っても、SQL Developer を再起動しても残ります。
- よく使う SQL は、履歴に頼らず `.sql` ファイルとして保存します（Ctrl+S）。チームの調査用 SQL は、リポジトリや共有フォルダにまとめておくと再利用しやすくなります。

## 手が止まる場面4：条件の値を変えるたびに SQL を書き換えている

**症状**

顧客 ID を変えて同じ SQL を何十回も実行するたびに、SQL の中の値を書き換えている。書き換え漏れで別の顧客のデータを見ていた。

**対処：バインド変数を使う。**

```sql
SELECT *
  FROM orders
 WHERE customer_id = :customer_id
   AND created_at >= :from_date;
```

- `:名前` と書いた部分は、実行時に**値の入力ダイアログ**が出ます。前回入力した値も覚えているので、変える部分だけ入力し直せます。
- 文字列はダイアログにそのまま `ABC001` と入力します（クォートは不要）。日付は `TO_DATE(:from_date, 'YYYY-MM-DD')` のように書式を指定しておくと、入力ミスを防げます。
- アプリの SQL（`?` や `:name` を使ったもの）をそのまま貼り付けて動作を確認できるのも利点です。

## 手が止まる場面5：結果を Excel や INSERT 文にするのに時間がかかる

**症状**

調査結果を表で共有したい。本番の一部データを、開発環境で再現するための INSERT 文にしたい。

**対処1：グリッドからコピー・エクスポートする。**

| 操作 | 方法 |
| --- | --- |
| 選択セルをコピー | Ctrl+C |
| **列名（ヘッダー）付きでコピー** | **Ctrl+Shift+C** |
| ファイルに出力（CSV / Excel / INSERT 文 / JSON など） | グリッドを右クリック →「エクスポート」 |
| 1行を縦に並べて見る | グリッドを右クリック →「単一レコード・ビュー」 |

Ctrl+Shift+C でコピーしたものは、Excel にそのまま貼り付けると列名付きの表になります。

**対処2：出力形式のヒントを書いて、スクリプト実行（F5）する。**

```sql
SELECT /*csv*/ * FROM orders WHERE status = 'NEW';

SELECT /*insert*/ * FROM m_customer WHERE customer_id = 'ABC001';
```

| ヒント | 出力形式 |
| --- | --- |
| `/*csv*/` | CSV |
| `/*insert*/` | INSERT 文（テーブル名・列名付き） |
| `/*json*/` | JSON |
| `/*html*/` | HTML の表 |
| `/*fixed*/` | 固定長のテキスト |

- ヒントは **F5（スクリプトの実行）のときだけ**有効です。Ctrl+Enter ではグリッドに通常どおり表示されます。
- ワークシート全体の出力形式をまとめて変えたいときは、先頭で `SET SQLFORMAT csv` を実行します（`SET SQLFORMAT` で元に戻ります）。
- **本番データを INSERT 文にして持ち出す場合は、個人情報や機密情報が含まれていないかを必ず確認**し、社内のルールに従ってください。

## 手が止まる場面6：SQL が遅い理由が分からない

**症状**

ある SELECT が数分かかる。インデックスが使われているのか分からない。

**対処：実行計画を見る。**

| 操作 | ショートカット | 内容 |
| --- | --- | --- |
| **計画の説明（Explain Plan）** | **F10** | SQL を実行せずに、Oracle がどう実行するつもりかを表示 |
| 自動トレース | F6 | 実際に実行して、実行計画と統計（読み込んだブロック数など）を表示 |

実行計画で、まず次の2点を確認します。

- 大きなテーブルに **`TABLE ACCESS FULL`**（全件読み込み）が出ていないか
- 想定したインデックスが **`INDEX RANGE SCAN`** などで使われているか

```text
OPERATION                    OBJECT_NAME        CARDINALITY   COST
SELECT STATEMENT                                        12      4
  TABLE ACCESS BY INDEX ROWID ORDERS                     12      4
    INDEX RANGE SCAN          IX_ORDERS_CUST_ID          12      1
```

- 自動トレースは**実際に SQL を実行する**ため、更新系の SQL や本番環境では使い方に注意します。まずは F10 で確認します。
- 自動トレースには、ユーザーに統計情報を参照する権限が必要です。エラーになる場合は DBA に相談します。

## 手が止まる場面7：テーブルやオブジェクトがどこにあるか分からない

**症状**

「`ORDER_DETAIL` を参照しているビューとプロシージャを全部洗い出して」と言われたが、どこから探せばいいか分からない。テーブルの CREATE 文がほしい。

**対処：オブジェクトの検索・DDL・依存関係を使う。**

| やりたいこと | 方法 |
| --- | --- |
| 名前でテーブル・ビュー・プロシージャを探す | 「表示 → データベース・オブジェクトの検索」 |
| テーブルの CREATE 文を取得する | テーブルを開いて「**SQL**」タブ |
| そのテーブルを使っているオブジェクトを調べる | テーブルを開いて「**依存性**」タブ |
| 列・制約・インデックスを確認する | テーブルを開いて「列」「制約」「索引」タブ |
| 新しいワークシートを開く | **Alt+F10** |
| 同じ接続で、別セッションのワークシートを開く | **Ctrl+Shift+N**（非共有ワークシート。長い SQL を実行中でも別の作業ができる） |

- 「非共有ワークシート」は**別のセッション**なので、コミットしていない変更は、元のワークシートからは見えません。ロック待ちの確認などにも使えます。
- 2つの環境（DEV と STG など）のテーブル定義の差分を調べたいときは、「ツール → データベース差分」が使えます。

## 作業を速くする機能（応用）

### コード・テンプレート

よく書く SQL を短い略語で呼び出せます。「ツール → プリファレンス → データベース → SQLエディタ・コード・テンプレート」で登録します。

| ID（略語） | テンプレート |
| --- | --- |
| `scnt` | `SELECT COUNT(*) FROM ` |
| `slock` | `SELECT * FROM v$locked_object` |

ワークシートで略語を入力して **Ctrl+Space** を押すと、テンプレートに展開されます。

### スニペット

「表示 → スニペット」で、関数や構文のひな形（日付関数、集計関数など）を一覧から選んで、ワークシートにドラッグできます。関数の書き方を忘れたときの辞書代わりになります。

### ワークシートのクリア

**Ctrl+D** でワークシートの中身をすべて消せます。消した内容は Ctrl+Z で戻せますが、**保存していない SQL を消さない**よう注意します。

## まとめ

- まず覚えるのは **Ctrl+Enter（1文実行）・F5（全文実行）・F11 / F12（コミット / ロールバック）**の4つです。特に、1文実行と全文実行の違いは事故防止に直結します。
- **Ctrl+F7（整形）・Ctrl+Space（補完）・F8（履歴）**を使うだけで、SQL を書く・読む・再利用する時間が大きく減ります。
- 結果の共有は **Ctrl+Shift+C** と **`/*csv*/` / `/*insert*/`**、遅い SQL の調査は **F10（実行計画）**から始めましょう。

導入から接続設定、初日の設定、ショートカットまで、ここまでの4本で SQL Developer を現場で安全かつ速く使うための基本はそろいます。
